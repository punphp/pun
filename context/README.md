# Project context

Everything a person or agent needs to know about where Pun stands lives in this folder. The public docs site is in
`docs/` and the brand in `design/`; neither holds internal notes.

| File | What it is | Edit when |
| --- | --- | --- |
| [PLAN.md](PLAN.md) | The plan, by component (C0-C14): goal, done, pending, open questions | A component's scope or status changes |
| [components/](components/) | One file per component we've walked through: how it works, its plan, open questions ([commands.md](components/commands.md) says which command owns which rule; then [format.md](components/format.md), [lint.md](components/lint.md)) | We discuss or change that component |
| [DECISIONS.md](DECISIONS.md) | Every decision the user has made | The user decides something |
| [TASKS.md](TASKS.md) | Task board: who is doing what, per component | You start or finish a task |
| [REQUESTS.md](REQUESTS.md) | Open asks from one component to another | You need an API you don't own |
| [RULES.md](RULES.md) | Rules design: placement, names, tiers, ignore comments (data in crates/pun-config/rules/mapping.toml) | Rule placement or naming changes |
| [reference/oracle.md](reference/oracle.md) | Pinned upstream versions, oracle scripts, exporters, delegate mode | An oracle version or script changes |
| [reference/tokens.md](reference/tokens.md) | pun-tokens API and why it has its own lexer | The token API changes |
| [reference/mago-extras.md](reference/mago-extras.md) | Mago capabilities with no Pint equivalent, and the `Pun/*` rules | A Mago-derived rule changes |
| [reference/lsp.md](reference/lsp.md) | `pun lsp` = PHPantom + Pun: evaluation and wiring steps | The LSP design changes |
| [reports/scoreboard.md](reports/scoreboard.md) | Format parity per corpus project, fuzz runs, benchmarks | Generated by `pun-harness format`; benchmark notes by hand |
| [reports/COVERAGE.md](reports/COVERAGE.md) | Line coverage per crate, exclusions, test audit | Generated by `scripts/coverage.sh`; exclusions by hand |
| [archive/](archive/) | The plan and task board as they were before the 2026-10-17 reset | Never; read-only history |

Rules of thumb: one fact lives in one file (link to it, don't copy it); decisions go in DECISIONS.md, not in a plan
section; finished task rows move to git history, not to a growing list.
