### Lint perf rounds

Each round reruns `BENCH=lint TOOLS=pun RUNS=10 scripts/bench.py pinkary laravel-framework` under
`HEAVY_EXCLUSIVE=1`, before and after, and keeps pun-lint's output byte-identical: the `check` problems and the `fix`
output of all 3,376 corpus files (`examples/dump`), and `fix_dir` against `rector process` with the ported rules
(`diff -r` empty on both projects). bench.py polls every 20 ms, which hides most of a 70 ms run, so each change is
also timed with 30 plain spawn-and-wait runs (median; "precise" below).

| 2 | pinkary | 44.0 ms, 13.8 MB | 44.4 ms, 13.8 MB | 9.5 ms, 13.7 MB | 7.5 ms, 13.3 MB |
| 2 | laravel-framework | 100.5 ms, 82.4 MB | 91.5 ms, 81.6 MB | 66.2 ms, 82.5 MB | 53.2 ms, 85.7 MB |
| 3 | pinkary | 44.3 ms, 12.9 MB | 43.4 ms, 13.4 MB | 7.8 ms, 13.3 MB | 7.65 ms, 13.3 MB |
| 3 | laravel-framework | 91.9 ms, 84.3 MB | 89.1 ms, 82.2 MB | 51.3 ms, 87.3 MB | 49.0 ms, 85.9 MB |

- round 1: the walk writes every report into one list and tags it with its rule ID, instead of a list per node
  drained into the results per rule, which cost an allocation check and a drain on each of ~2.4M nodes. wall -8%
  (laravel-framework, precise), rss 0%.
- round 1: `no-unused-catch-variable` visits only `try` nodes and finds their statement list two ancestors up,
  instead of collecting the statement children of every node. wall -4%, rss 0%.
- round 1: rules name the node kinds they report on (`Rule::targets`, as in Mago's linter) and the engine calls a
  rule only on those kinds; a rule without targets still sees every node. wall -6%, rss -1%.
- round 1 total: laravel-framework wall -17% precise (-6% bench.py), rss -1 to -2%; pinkary wall -6% precise (-2%
  bench.py), rss -4 to -8%; single-thread CPU (`examples/cost`) 67.2 to 40.5 us per file. What is left is Mago's
  parser (about 70% of user time), the tree walk (Mago's `visit_children` on every node, about 25%), and file opens
  (most of the system time). Peak memory is the Mago arenas of the files parsed at the same time; a reused
  per-thread arena did not change wall time and raised peak memory by 9 MB, so it was dropped.
- round 2: `examples/check` (the bench's driver) walks the directories on its worker threads: one stack holds the
  directories still to list and the files still to check, so checking starts with the first directory instead of
  after a single-threaded walk of the whole tree, and an entry's type comes from the directory listing instead of a
  `stat` per entry. The walk alone took 15.7 ms of laravel-framework's 66 ms (9.6 ms without the `stat`s). wall -20%
  precise on both projects (-9% bench.py on laravel-framework; pinkary's 9.5 ms run sits under bench.py's 44 ms
  floor), rss +4% on laravel-framework (the threads start parsing at once; a FIFO stack was +14%) and -3% on
  pinkary (bench.py: -1% and 0%). The engine is unchanged: `check` problems and `fix` output are byte-identical.
- round 2, no change: the engine itself has nothing over 3% left. Single-thread over laravel-framework's sources in
  memory, Mago's parse is 89 ms, parse plus the walk 127 ms, and the full `check` with both rules 127 ms, so the
  rules cost under 1%. The walk (29%) is Mago's `visit_children` on 5.2M nodes; skipping the 1.1M nodes of kinds
  that never have children made it slower (93 vs 78 ms over pre-parsed trees). Opening files is the largest system
  cost (25% of samples, `open` itself): `openat` on a held directory handle and more threads (12, 16, 24) did not
  change wall time. Peak memory is Mago's arenas: the 462 KB `ValidationValidatorTest.php` takes a 26 MB arena
  (39k 376-byte allocations make 14.7 MB), so one thread alone peaks at 36 MB; only a change in Mago's parser
  would cut it.
- round 3: `Linter::check` walks the tree with Mago's typed `Walker` instead of recursing through
  `Node::visit_children`. The walker has one function per node type, inlined into its parent's, where the old walk
  matched on `Node` and called a closure for each of laravel-framework's 5.2M nodes. A hook per node type pushes the
  same `Node` onto the ancestor stack, and overrides for the 11 types where the walker and `visit_children` disagree
  (keywords, terminators, field order, the two `TraitUseAdaptation` cases) keep the nodes, their order and their
  ancestors identical: equal on 17,438 files (the corpus, phpstan-src's tests, rector-src) and in `tests/walk.rs`.
  Over pre-parsed trees the walk with ancestors went from 79 to 53 ms; single-thread `check` from 40.9 to 33.9 us
  per file (-17%). wall -4.5% precise and -3% bench.py on laravel-framework, -2% on pinkary (under bench.py's
  44 ms floor); rss -1 to -2.5% on laravel-framework, flat on pinkary (bench.py's 13 MB sample moves by 0.5 MB run
  to run). The walk also needs less stack: 6,619 nested `.` operands fit in a 1 MB thread, against 1,652 before.
- round 3, no change: what is left is outside the engine. Of the samples of a laravel-framework run, 33% are the
  kernel's `open` (11 us per file on this machine, against 1.4 us for a `stat`; four threads open faster than eight,
  but a gate of 1-4 concurrent opens in `examples/check` was slower), 35% Mago's parser, 12% the walk. Copying the
  source into the arena (`parse_file_content`) is 2.3%, under the 3% bar, and avoiding it needs a `'static` borrow
  of the source.
- round 4: `examples/check` reads on 3 threads of its own and checks on one thread per core, where every thread used
  to both read and check. `open` costs 10.5 us per file here (a `stat` 1 us) and slows down past 4 concurrent
  callers: 8 threads read laravel-framework's files in 24 ms, 4 in 15 ms. With 8 threads opening, the run spent
  0.14-0.27 s of system time; with 3 readers 0.08-0.11 s, and the checkers parse while the readers wait in `open`.
  2, 3, 4 and 5 readers took 46, 43, 44 and 47 ms. laravel-framework wall -10% precise, rss -5%; pinkary -8%
  precise. The engine is unchanged.
- round 4: `Linter::check` parses with `parse_file_borrowed_with_settings` on a `File` that borrows the source,
  instead of `parse_file_content`, which copied the whole source into the arena first (`alloc_slice_copy`, 2.2% of
  samples). The borrow is `'static` only on paper: the `File` and the tree die before `check` returns. Single-thread
  `check` (`examples/cost`) 33.5 to 31.4 us per file (-6%); wall -2% precise, rss -3% (the arena no longer holds a
  copy of the source).
- round 4 total: laravel-framework wall -12% precise (47.5 to 41.5 ms) and -26% bench.py (88.1 to 65.3 ms, the
  medians of two 10-run calls each), rss -7%; pinkary wall -11% precise, flat in bench.py (its 8 ms run sits under
  bench.py's 44 ms floor), rss -4%. Output byte-identical: `examples/dump` on all 3,376 corpus files, and
  `fix_dir` against `rector process` with the ported rules (`diff -r` empty on both projects).

  laravel-framework 94.4 to 86.5 ms (-8%), 89.8 to 82.1 MB (-9%); the after runs are bimodal (46-56 ms or 85-99 ms),

  state: laravel-framework about 71-75 to 64-66 ms (-9 to -12%), rss -5%; pinkary 10.2-10.7 to 9.8-9.9 ms. Output
  identical (dump on 3,376 files; `fix_dir` against `rector process` on laravel-framework, 9 files).
- round 4, what is left: in a laravel-framework profile the checkers now wait for sources (`__psynch_cvwait`) in
  42% of the samples and `open` is 15%, so the readers are the critical path again and each of them spends 82% of
  its time in `open`. Mago's parser is 18% and the walk 6%. More readers make `open` slower, not faster.
- round 5, no change: nothing over 3% is left. Before (and after): bench.py RUNS=10 pinkary 43.3 ms, 12.7 MB and
  laravel-framework 45.6 ms, 78.6 MB; precise laravel-framework 40.7-41.8 ms, 78-80 MB, pinkary 6.7-6.9 ms,
  12.8 MB. On laravel-framework, 35 ms of the 41 ms run is spent in the process and 3 ms is the fixed cost of
  starting it (an empty directory takes 3.0 ms). The run uses 0.18 s user and 0.07 s system time, so 7.1 of the
  8 cores are busy and the run is CPU-bound. The readers finish at 34 ms, and alone, without parsing, they take
  26.6 ms. So the wall time follows the total CPU time: removing the walk (an experiment) cut wall time 13%
  (41.9 to 36.2 ms). Single-thread `check` is 80% Mago's parser and 19% the walk. Of the walk, about 11 ms of
  95 ms is Pun's hooks (the ancestor push and pop and the rule lookup), and about 10 ms is Mago's bare walker.
  None of these tries moved wall time outside the run-to-run noise:
  - Leaf node types skip the ancestor push and pop, and a per-kind table replaces the rule lookup. Single-thread
    `check` went from 95.5 to 93.3 ms (-2.2%).
  - 5, 6 or 7 checkers, 2 or 4 readers, and QoS classes on either kind of thread.
  - Handing sources to the checkers through park/unpark, or through an mpsc channel, instead of a condvar.
  - Reading each file with a single `read`, with the UTF-8 check moved to the checkers.
  - A reused arena on each checker thread: +30 MB.
  - mimalloc: +1.5 ms and +52 MB.

  `open` costs 10.5 us per file on one thread and 15 us on three, whatever the flags. The corpus files'
  `com.apple.provenance` xattr cannot be removed (`xattr -d` leaves it), so the round 4 follow-up about it is
  still open.
- round 6, no change: nothing over 3% is left in pun-lint. Before (and after): bench.py RUNS=10 pinkary 45.0 ms,
  12.5 MB and laravel-framework 44.0 ms, 78.4 MB; precise laravel-framework 41.0-43.6 ms, 80-81.5 MB, pinkary
  6.8 ms, 12.9 MB. Both bench.py times sit at its polling floor (20 ms sleeps), so only its memory column can move.
  A 20-run profile of laravel-framework has the same split as round 5: `open` 17% of samples, Mago's parser 18%,
  the walk 6%, and idle checkers waiting for sources 42%. Single-thread, `check` is 79% Mago's parser (lexer 15%,

  - Sizing each file's arena up front (`LocalArena::with_chunk_size`, 16, 32, 64 or 128 times the source length)
