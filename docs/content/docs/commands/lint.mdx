---
title: pun lint
description: Report code issues and apply available fixes with --fix.
---

```bash
pun lint
pun lint --fix
```

`pun lint` reports `[lint]` findings without editing files. `--fix` applies available fixes. Rules include risky and code-deleting PHP-CS-Fixer fixers, Rector ports, and Mago ports.

Lint does not format the result. [`pun check --fix`](/docs/commands/check) runs both.

## Configure rules

Rules accept a level or a table with a level, fix setting, and options:

```toml pun.toml
[lint]
sets = ["dead-code", "modernize"]

[lint.rules]
"style/require-final-class" = "error"
"types/no-loose-comparison" = { level = "warn", fix = "off" }
"style/no-short-ternary" = "off"
```

| Value | Meaning |
| --- | --- |
| `"error"` | Report, and fail the run |
| `"warn"` | Report |
| `"off"` | Disable |
| `{ fix = "off" }` | Report, never apply |

Rules with `fix = "off"` remain report-only, including under `--fix`. Only errors fail the run unless a warning limit is set.

Rule selection follows [sets, groups, rules, and path overrides](/docs/configuration/pun-toml#lint). Options belong in `[lint.rules]`; path overrides accept levels only. The [rule reference](/docs/rules/lint) lists individual checks, options, and implementation status.

## Levels on the command line

```bash
pun lint -A lint/style
pun lint -W security/no-global
pun lint -D lint/security -A security/no-eval
pun lint --deny-warnings
pun lint --max-warnings 10
```

`-A` disables a rule or group, `-W` selects warnings, and `-D` selects errors. Flags apply after config and path overrides, in command-line order. The last matching flag wins.

Groups select implemented rules only. Naming an unimplemented rule directly is a configuration error.

`--deny-warnings` fails on any warning. `--max-warnings N` fails on more than `N` warnings.

Lint also accepts [`pun format`'s file-selection and output flags](/docs/commands/format#pints-flags), such as `--dirty`, `--diff`, `--staged`, `--format`, and `--stdin`.

## Output

Native lint rules report code frames and fixability. Token-based PHP-CS-Fixer ports report each affected file and its rule IDs. `--concise` prints one line per problem.

`--format` selects `json`, `txt`, `checkstyle`, `junit`, `xml`, `gitlab`, `github`, or `agent`. Non-GitHub machine reports use Pint's per-file shape.

## Files

Lint applies shared and lint-specific paths and exclusions. It skips Blade templates, `vendor/`, `bootstrap/cache`, `build`, `node_modules`, and `storage`. [`pun list-files --command lint`](/docs/commands/list-files) shows the selection.

The `types/*` rules look up classes in every file lint selects, even when you name only some of them. They also look up classes that Composer autoloads: the generated `vendor/composer/autoload_classmap.php`, then the psr-4 and psr-0 directories in `composer.json` and `vendor/composer/installed.json`. Rector's PHPStan finds the same classes through the autoloader. A method that overrides a parent method gets a return type only when both classes are in `vendor/` or both are outside it.
Rules ported from Rector read types the way Rector 2.8.4 does with PHPStan 2.3.5, the version it requires. In a trait, only `$this` and the trait's own members have no type.
`types/add-return-type-from-constant` reads documented constant types. Anonymous classes are final for late-static constant lookup.
Property-type rules preserve relative `parent` hints from constructors and accessors instead of replacing them with the parent's class name.
Their PHPDoc cleanup also applies Rector's scalar-type comparison to scalar-only unions.
Constructor initialization detection recognizes same-class named static calls and property assignments, including imported and qualified class names.
It also follows documented peer receivers and inherited helper declarations, including external and generic receivers.
Only direct, first-level helper assignments count. Helper calls do not recurse through other helpers.
Class-name case rules and ambiguous intersection receivers follow Rector's distinct call and assignment checks.
Object-type comparison preserves intersection constraints and removes a constraint only when class reflection proves it redundant.

Fix rounds refresh closure and arrow-function signatures after source edits.
Moving a closure preserves its parameters, return type, and captured variables.

## Ignore comments

```php
$x = eval($code); // @pun-ignore lint/security/no-eval -- legacy plugin loader
```

Token-based PHP-CS-Fixer ports support only `@pun-ignore-file`. Other lint rules also support line and region ignores. A bare ignore without a rule ID is an error.

See [ignore comments](/docs/configuration/ignore-comments) for all forms and unused-ignore checks.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | No remaining errors and no warning limit exceeded |
| 1 | Remaining errors or a warning limit exceeded |
| 2 | Pun could not run |
