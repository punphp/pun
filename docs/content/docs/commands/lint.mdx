---
title: pun lint
description: Report and fix code rules that change behaviour, from PHP-CS-Fixer's risky fixers, Rector and Mago.
---

```bash
pun lint          # report what the [lint] rules would change
pun lint --fix    # apply the fixes of every enabled rule
```

Lint rules are the ones that can change what code does, so Pun applies them only with `--fix`. They include PHP-CS-Fixer's risky fixers (`final_class`, `strict_comparison`, `declare_strict_types` and the rest), the PHP-CS-Fixer fixers that delete or restructure code (`no_unused_imports`, `no_useless_return`, `phpdoc_no_package` and 37 more), Rector's rules, and the extra rules ported from Mago.

## Configure rules

Each rule under `[lint.rules]` takes a level, or a table with `level`, `fix = "off"` and the rule's options:

```toml pun.toml
[lint]
sets = ["dead-code", "modernize"]

[lint.rules]
"style/require-final-class" = "error"
"types/no-loose-comparison" = { level = "warn", fix = "off" }   # reported, never applied
"style/no-short-ternary" = "off"
```

| Value | Meaning |
| --- | --- |
| `"error"` | Report, and fail the run |
| `"warn"` | Report |
| `"off"` | Disable |
| `{ fix = "off" }` | Report, never apply |

`--fix` applies the fix of every enabled rule. `pun lint --fix` lists what it did not apply (rules with `fix = "off"`) as remaining, like `pun lint` reports it, and exits 1 when anything remains.

`pun lint` exits 0 when clean, 1 on any `error`, and 2 when Pun couldn't run (a bad `pun.toml`, an unported rule, an unreadable path, a rule that failed on a file); see [exit codes](/docs/commands/format#exit-codes). Under GitHub Actions (`GITHUB_ACTIONS=true`), or with `--format=github`, each file a rule can fix gets an annotation (`::error file=app/L.php,line=3,col=0,title=lint/style/no-alias-function::lint/style/no-alias-function can fix this file`).

Options for a rule go in the same table. Rule names are Pun IDs, `<group>/<name>` inside `[lint.rules]` (`lint/<group>/<name>` in full); an earlier Pun name or a PHP-CS-Fixer name gets an error that names its Pun ID.

Which rules run comes from your [lint sets](/docs/configuration/presets#lint-sets), `[lint.groups]` and `[lint.rules]` ([pun.toml](/docs/configuration/pun-toml#lint)). `pun migrate` moves the risky and code-deleting rules your `pint.json` enabled here at `"error"`, so `pun check --fix` applies them as Pint did.

## Mago's report-only rules

```bash
pun lint --mago            # the whole project
pun lint --mago app routes # specific paths
```

Reports Mago's lint-only Laravel rules as `path:line:col: level [rule] message`. These have no auto-fix, so this never edits files. It exits 1 when it finds something.

| Rule | Flags |
| --- | --- |
| `no-request-all` | `$request->all()` |
| `prefer-casts-method` | a `$casts` property instead of a `casts()` method |
| `prefer-anonymous-migration` | named migration classes |
| `prefer-view-array` | `view()->with()` chains instead of an array |
| `middleware-in-routes` | middleware set in controllers instead of routes |
