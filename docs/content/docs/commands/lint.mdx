---
title: pun lint
description: Report and fix code rules that change behaviour, from PHP-CS-Fixer's risky fixers, Rector and Mago.
---

```bash
pun lint          # report what the [lint] rules would change
pun lint --fix    # apply the rules marked fix = "apply"
```

Lint rules are the ones that can change what code does, so Pun never applies them unless you say so. They include PHP-CS-Fixer's risky fixers (`final_class`, `strict_comparison`, `declare_strict_types` and the rest), Rector's rules, and the extra rules ported from Mago.

## Configure rules

Each rule under `[lint.rules]` takes a severity, or a table with a `fix` mode and options:

```toml pun.toml
[lint.rules]
require-final-class = { fix = "apply" }   # applied by --fix
no-loose-comparison = "warn"              # reported, never applied
prefer-early-return = "error"
no-short-ternary = "off"
```

| Value | Meaning |
| --- | --- |
| `"error"`, `"warn"`, `"info"` | Report at that severity |
| `"off"` | Disable |
| `{ fix = "apply" }` | Report, and apply with `--fix` |
| `{ fix = "safe-only" }` | Report; apply only fixes marked safe |
| `{ fix = "off" }` | Report, never apply |

`pun lint --fix` lists what it did not apply (rules without `fix = "apply"`) as remaining, like `pun lint` reports it, and exits 1 when anything remains.

Options for a rule go in the same table. Rule names are Pun IDs; a PHP-CS-Fixer name gets an error that names its Pun ID.

Which rules run by default comes from your [preset](/docs/configuration/presets). `pun migrate` moves the risky rules your `pint.json` enabled here with `fix = "apply"`, since Pint applied them unattended.

## Mago's report-only rules

```bash
pun lint --mago            # the whole project
pun lint --mago app routes # specific paths
```

Reports Mago's lint-only Laravel rules as `path:line:col: level [rule] message`. These have no auto-fix, so this never edits files. It exits 1 when it finds something.

| Rule | Flags |
| --- | --- |
| `no-request-all` | `$request->all()` |
| `prefer-casts-method` | a `$casts` property instead of a `casts()` method |
| `prefer-anonymous-migration` | named migration classes |
| `prefer-view-array` | `view()->with()` chains instead of an array |
| `middleware-in-routes` | middleware set in controllers instead of routes |
