---
title: pun format
description: Format PHP layout, casing, and spelling without code refactors.
---

`pun format` applies `[format]` rules from `pun.toml`. Risky and code-deleting Pint fixers belong to [`pun lint`](/docs/commands/lint). [`pun check --fix`](/docs/commands/check) runs both.

```bash
pun format
pun format --test
pun format app/Models
```

## Pint's flags

These flags retain Pint's behavior unless noted:

| Flag | What it does |
| --- | --- |
| `--test` (`--check`) | Test for style errors without fixing them. Exits 1 on any. |
| `--bail` | Like `--test`, stopping at the first error. |
| `--repair` | Fix errors, but exit 1 if anything changed. |
| `--dirty` | Only files with uncommitted changes. |
| `--diff=<branch>` | Only files changed since branching off `<branch>`. |
| `--blade` | Also format Blade files. |
| `--config=<path>` | Use this `pun.toml`. |
| `--preset=<name>` | Use `laravel`, `psr12`, or `empty` instead of `pun.toml`. For `per` or `symfony`, use `pun migrate --preset <name>`. |
| `--no-config` | Use the `laravel` preset and no config file. |
| `--format=<fmt>` | Select `json`, `txt`, `agent`, `checkstyle`, `junit`, `xml`, `gitlab`, or `github`. |
| `--output-to-file=<path>` | Also write a report to a file. `--output-format=<fmt>` selects its format. |
| `--stdin-filename=<path>` | Path context for code read from stdin (`-` as the path). |
| `--cache-file=<path>` | Accepted and ignored, as is `--no-cache`. Pun has no cache and checks every file on every run. |
| `-v`, `-q` | `-v` adds unchanged files and diffs. `-q` suppresses successful output. |
| `--parallel` | Accepted. Pun always runs in parallel, one thread per core. |
| `--max-processes=N` | Cap threads and Prettier workers. Invalid or nonpositive values keep the default. |

## Pun's own flags

| Flag | What it does |
| --- | --- |
| `--staged` | Select files with staged changes. Reads working-tree contents, not the index. |
| `--since=<ref>` | Only files changed since a commit, plus untracked files. |
| `--watch` | Keep running and re-format files as they change. |
| `--stdin` | Read code from stdin; `--stdin-filename` gives it a path for exclusion rules. |
| `--explain` | Print the fixers the run applies, in priority order. |
| `--color=auto\|always\|never` | Select color mode. `auto` respects `NO_COLOR`. `--ansi` and `--no-ansi` also work. |

## Output

Default output lists changed files and rule IDs, followed by a summary:

```
$ pun format
 ✔ app/Http/Kernel.php        format/whitespace/no-trailing
 ✔ app/Models/User.php        format/imports/ordered
Formatted 2 files, 482 unchanged · 484 files in 0.21s
```

`--test` reports changes without writing them. Syntax errors include code frames. Unchanged files are hidden unless `-v` is set.

Piped output has no spinner or automatic color. Non-UTF-8 terminals use ASCII status symbols.

Machine reports retain Pint's formats. `--format=agent` is Pint's JSON reporter, not Pun's automatic [coding-agent output](/docs/guides/coding-agents).

## Exit codes

| Code | When |
| --- | --- |
| 0 | No changes needed, or all changes applied |
| 1 | Formatting changes in test or repair mode, or a syntax error |
| 2 | Pun could not run: invalid config, unsupported rule, unreadable file, report error, or missing Blade dependency |

Pint exits 1 for run errors. Pun exits 2 and prints an error with a hint on stderr. With `--format` or `-q`, it retains Pint's error box on stdout.

## GitHub Actions

Under `GITHUB_ACTIONS=true`, default output includes an annotation for each file that needs formatting. `--format=github` prints only annotations:

```
::error file=app/Models/User.php,line=12,col=0,title=format/arrays/syntax::File needs formatting
::error file=app/Broken.php,line=3,col=1,title=syntax-error::Unclosed '(' on line 2
```

Fixed files get no annotation. A run error uses `::error ::<message>`.

## Configuration errors

Without `pun.toml`, use `pun init`, `pun migrate`, `--preset`, or `--no-config`.

Enabling an unimplemented rule is a configuration error. Pun names the rule and exits 2 before editing files. It never runs PHP as a fallback.
