---
title: pun migrate
description: Convert existing tool configs to pun.toml and report unsupported items.
---

```bash
pun migrate
pun migrate --from pint
pun migrate --yes
pun migrate --dry-run
```

Migration writes supported settings and reports items it skips. Exit code 0 does not mean every rule was migrated. Review the warnings before replacing your existing tools.

## Config discovery

Pun looks in the project root:

| Tool | Files | Becomes |
| --- | --- | --- |
| Pint | `pint.json` or `--config` | `[files]`, `[format]`, and `[lint.rules]` |
| PHP-CS-Fixer | `.php-cs-fixer.php`, `.php-cs-fixer.dist.php` | Same as Pint |
| Rector | `rector.php` | `[lint]` |
| PHPStan | `phpstan.neon`, `phpstan.neon.dist`, `phpstan.dist.neon` | `[analyse]` |
| Mago | `mago.toml` | Detected but not translated |

On a terminal, a checklist selects the configs to migrate. All detected configs start selected.

`--from pint,phpstan` selects tools without a prompt. Without a terminal, under an agent, or with `--yes`, Pun migrates every detected config unless `--from` limits the selection.

When both Pint and PHP-CS-Fixer are selected, Pint supplies the format config. With no source config, Pun offers a starter based on the `laravel` preset or `--preset`.

## Pint and PHP-CS-Fixer

Pint migration resolves `extend`, `--config`, and `--preset`. PHP-CS-Fixer migration executes the config through PHP-CS-Fixer with system PHP.

Reading a `.php-cs-fixer.php` or a `rector.php` runs project code: both files are PHP, and Pun loads `vendor/autoload.php` first. Run `pun migrate` only on a checkout you trust.

- Layout rules become `[format.rules]` overrides.
- Risky and code-deleting fixers become `[lint.rules]` at `"error"`.
- Finder paths and `exclude` become `[files] paths` and `exclude`, so lint and analyse skip the excluded folders too. `notName` and `notPath` become format exclusions. [Two exclusion details](/docs/configuration/pint-json) differ from Pint.
- `per`, `symfony`, and rule sets such as `@PER-CS` expand into explicit rules over `preset = "empty"`.
- Options use [Pun names and values](/docs/configuration/pun-toml#rule-options).

The starter also enables Pint's risky and code-deleting preset rules under lint. Use `pun check --fix` to apply both kinds of rule.

See the [Pint mapping](/docs/migrate/from/pint) and [PHP-CS-Fixer mapping](/docs/migrate/from/php-cs-fixer).

## Rector

Rector migration requires system PHP and the project's installed Rector, so run `composer install` first. Prepared sets map to lint sets; `type-declaration` maps to `types`.

Explicit rules, set differences, and path skips become rule settings, exclusions, and path overrides. Configured rule keys use kebab-case; lists use `items`.

Some Rector rules only change layout, such as `ReplaceMultipleBooleanNotRector` (`!!$x` to `(bool) $x`). In Pun these are format rules, and Rector migration never writes format settings. If your format config already runs the rule, nothing changes. Otherwise migration reports the rule and names the format rule to turn on in `[format.rules]`. The `laravel` preset runs all of them except `NewMethodCallWithoutParenthesesRector` and `ShellExecFunctionCallOverBackticksRector`.

Custom rules, closures, null configurations, and out-of-scope upgrade rules are skipped. See the [Rector mapping](/docs/migrate/from/rector).

## PHPStan and Larastan

Migration resolves includes the way PHPStan does, so an include under `vendor/`, such as Larastan's `extension.neon`, needs `composer install` first. When that include is missing, `phpstan.neon` is left untouched with a warning and the other configs are migrated; run `pun migrate` again after `composer install`. A missing include outside `vendor/` stops the migration with exit code 2.

Migration converts levels to an analyse preset with explicit rule differences. It also converts paths, exclusions, stubs, ignore entries, and supported extension settings.

The analysis CLI does not yet apply every migrated setting, including stubs and ignore tables. See [analysis limitations](/docs/commands/analyse#configuration), the [PHPStan mapping](/docs/migrate/from/phpstan), and the [Larastan mapping](/docs/migrate/from/larastan).

PHPStan baselines are not copied. Generate a Pun baseline with `pun analyse --generate-baseline`, then configure `[analyse] baseline`.

## Ignore comments

`@php-cs-fixer-ignore` becomes `@pun-ignore-file`. Recognized `@phpstan-ignore` identifiers become Pun rule IDs. Unknown identifiers and blanket PHPStan ignores stay unchanged and are reported.

See [ignore comments](/docs/configuration/ignore-comments).

## File changes and errors

`--dry-run` prints a diff without writing. A second migration leaves identical output unchanged and refuses to overwrite a differing `pun.toml`.

Migration leaves source configs and dependencies in place. It may rewrite ignore comments in PHP files. It does not edit scripts, CI, hooks, or editor settings.

Writes are not transactional: a write error can leave earlier changes in place. Exit code 2 means migration could not complete.
