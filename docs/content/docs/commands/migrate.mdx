---
title: pun migrate
description: Move a project onto one pun.toml from pint.json, .php-cs-fixer.php, rector.php and phpstan.neon, with zero behaviour change.
---

```bash
pun migrate                    # on a terminal: a checklist of the configs it found
pun migrate --from pint        # only these (comma-separated: pint, php-cs-fixer, phpstan, rector, mago), no prompt
pun migrate --yes              # everything it found, no prompt
pun migrate --dry-run          # show what it would write, change nothing
```

## Choosing what to migrate

`pun migrate` looks for these in the project root and lists only the ones it finds, each with its file:

| Tool | Files | Becomes |
| --- | --- | --- |
| Pint | `pint.json` (or `--config`) | `[files]`, `[format]`, and `[lint.rules]` for the risky fixers |
| PHP-CS-Fixer | `.php-cs-fixer.php`, `.php-cs-fixer.dist.php` | the same as Pint |
| Rector | `rector.php` | `[lint]` |
| PHPStan | `phpstan.neon`, `phpstan.neon.dist`, `phpstan.dist.neon` | `[analyse]` |
| Mago | `mago.toml` | not supported yet |

On a terminal it shows a checklist with every found config checked; space toggles, enter confirms, Esc cancels. Only
the checked ones are migrated. Without a terminal, under a [coding agent](/docs/guides/coding-agents), with `--yes`
or with `--from`, it never asks: `--from` picks, otherwise everything found is migrated.

With pint.json and a `.php-cs-fixer.php` both picked, pint.json gives `[format]`, as in Pint. With neither found,
`[format]` gets Pint's default (laravel, or `--preset`). Leaving both out of the selection writes nothing.

```text
$ pun migrate --yes
 ✔ pint.json         → [format] preset laravel, 2 rules changed, 15 rules → [lint]
 ✔ rector.php        → [lint] sets dead-code, code-quality, modernize; 12 on, 40 off, 2 paths excluded
 ✔ phpstan.neon      → [analyse] preset max (level 10), 0 on, 7 off, 3 error patterns ignored
 ⚠ 105 Rector rules  only in php52..php83 upgrade sets (below the PHP 8.4 floor); skipped
 ⚠ vendor/phpstan/phpstan/conf/bleedingEdge.neon  Pun checks as PHPStan does without bleeding edge; skipped
   Want them? Send a PR to https://github.com/punphp/pun
 ⚠ phpstan-baseline.neon was not copied. Run `pun analyse --generate-baseline` for a Pun baseline.
 ✔ Wrote pun.toml
```

Everything Pun can't take is one ⚠ line with its reason, followed once by the request to send a PR. The rest is
written, and migrate exits 0. Mago's config is listed as not supported yet and left untouched. With no config at all
it says so and offers a starter pun.toml (written without asking when there is no terminal):

```toml
[format]
preset = "laravel"
```

The starter's `[lint.rules]` also lists the risky and code-deleting rules Pint's laravel preset applies, so
`pun check --fix` still matches `pint`.

Pun reads only `pun.toml`, so `pun migrate` is the one place the old configs are read. Migration changes no
behaviour: `pun check --fix` writes the same bytes Pint did, `pun lint` runs the rules Rector ran, and `pun analyse`
runs the checks PHPStan ran.

<Steps>
  <Step title="pint.json and .php-cs-fixer.php">

Reads `pint.json` the way Pint does (`extend`, `--config`, `--preset`), or a `.php-cs-fixer.php` through PHP-CS-Fixer itself. `[format]` gets the preset plus only what differs from it. The risky fixers and the fixers that delete or restructure code (`no_unused_imports`, `no_superfluous_phpdoc_tags`, ...) go under `[lint.rules]` at `"error"`, so `pun check --fix` applies them as Pint did. Pint's `in`, or the `in()` folders of a Finder, become `[files] paths`, and `exclude`, `notName` and `notPath` become `[format] exclude`, `not-name` and `not-path`. Rule sets such as `@PER-CS` are expanded into explicit rules. Rule options are written under their [Pun names](/docs/configuration/pun-toml#rule-options); an option PHP-CS-Fixer would reject stops the migration with PHP-CS-Fixer's own message.

  </Step>
  <Step title="rector.php">

Read through the project's own Rector with the system PHP (run `composer install` first). Rector's prepared sets become `[lint] sets` one to one (`type-declaration` is `types`) and its PHP sets the `modernize` set. Every rule Rector runs is matched to its Pun rule; then `[lint.rules]` gets `"error"` for each one no set turns on and `"off"` for each set rule Rector didn't run, so `pun lint` runs exactly Rector's rules. A rule skipped for some paths is off in a `[[lint.overrides]]`, a skipped path goes to `[lint] exclude`, and files outside `withPaths()` are excluded. A Rector rule that is a format rule in Pun (such as `CommonNotEqualRector`, `format/operators/standardize-not-equals`) is left to `[format]`, and named when the format config doesn't run it. A configured rule (`->withConfiguredRule()`) gets its configuration as the rule's options: keys kebab-cased, a list under `items`, as in `"refactor/rename-function" = { split = "explode" }`. Custom rules, configurations pun.toml can't hold (a closure, a null), and the upgrade rules below Pun's PHP 8.4 floor are named and skipped.

  </Step>
  <Step title="phpstan.neon">

Resolved the way PHPStan resolves it, includes and all. The level becomes the [analyse preset](/docs/configuration/pun-toml) that holds it, plus `"on"` and `"off"` lines so that exactly the checks PHPStan ran at that level run. Larastan, strict-rules and deprecation-rules are built in, so their checks count only when the config includes them, each only when its parameter (such as `strictRules.disallowedEmpty`) is on; without Larastan the `laravel` group is off. A strict-rules check that is a lint rule in Pun is turned on in `[lint.rules]`. `paths`, `excludePaths` and `stubFiles` become `[analyse] paths`, `exclude` and `stubs`, and each `ignoreErrors` entry becomes an `[[analyse.ignore]]` table under its Pun rule:

```toml
[[analyse.ignore]]
rule = "undefined/method"
identifier = "method.notFound"
message = "#^Call to an undefined method#"
paths = ["app/Models/User.php"]
count = 2
```

A parameter the project changes from PHPStan's default becomes an option, kebab-cased, of each running rule that reads it (`checkFunctionNameCase: true` gives `"undefined/function" = { check-function-name-case = true }`). Parameters the level sets are left to the preset. `@phpstan-ignore a.b (why)` comments become `@pun-ignore <rule IDs> -- why`; an identifier Pun doesn't know and `@phpstan-ignore-line` / `-next-line` are left and named. On a terminal, migrate then offers the closest preset, with how many problems the switch adds and removes; yes drops the `"on"` and `"off"` lines.

Other extensions, the project's own neon files, `bleedingEdge.neon` and parameters pun.toml has no key for are named and skipped.

  </Step>
  <Step title="Baselines">

Baselines are never copied. For each `phpstan-baseline.neon` the config includes, migrate prints the note to run `pun analyse --generate-baseline`.

  </Step>
  <Step title="Ignore comments">

`// @php-cs-fixer-ignore rule` becomes `// @pun-ignore-file format/<group>/<name>`. See [Ignore comments](/docs/configuration/ignore-comments).

  </Step>
</Steps>

Running it twice changes nothing the second time. Migrate edits no Composer scripts, CI steps or editor settings, and
it leaves the old config files and dev dependencies in place, so rolling back is reverting one commit.
