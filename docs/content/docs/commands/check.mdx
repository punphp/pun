---
title: pun check
description: Report format, lint, and analysis findings. Apply format and lint fixes with --fix.
---

```bash
pun check
pun check --fix
```

`pun check` reports findings without editing files. `--fix` applies formatting and available lint fixes, except rules with `fix = "off"`. Analysis never edits files.

## Rule order

Token-based format and lint fixers run in PHP-CS-Fixer's priority order to preserve Pint compatibility. Pun also runs native lint rules, then analyses the project. The combined command does not yet share one parse across all three stages.

A migrated Pint configuration uses `pun check --fix`, not `pun format`: risky and code-deleting Pint fixers are lint rules. Review [migration warnings](/docs/commands/migrate) before relying on equivalent output.

## Options

`pun check` accepts the [format flags](/docs/commands/format#pints-flags) and [lint level flags](/docs/commands/lint#levels-on-the-command-line). Analysis uses `[analyse]` settings, ignore comments, and the configured baseline.

```bash
pun check --dirty
pun check --staged
pun check --deny-warnings
pun check --format=github
```

`--staged` selects files with staged changes but reads their working-tree contents. It does not read only the staged diff.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | No remaining errors or format changes |
| 1 | Format changes, lint errors, analysis errors, or a warning limit exceeded |
| 2 | Pun could not run |

Use the individual commands for editor integration or to run one stage. Use [`pun analyse`](/docs/commands/analyse) for PHPStan-compatible reports.
