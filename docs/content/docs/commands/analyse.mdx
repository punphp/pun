---
title: pun analyse
description: Report type errors without editing files. PHPStan and Larastan support is incomplete.
---

```bash
pun analyse
pun analyse app tests
```

`pun analyze` is an alias. The [rule reference](/docs/rules/analyse) lists implemented and Planned checks. Pun does not yet replace every PHPStan or Larastan check.

## Configuration

```toml pun.toml
[analyse]
preset = "strict"
paths = ["app", "tests"]

[analyse.rules]
"types/missing-return-type" = "off"
```

The five [analyse presets](/docs/configuration/presets#analyse-presets) group PHPStan levels. Individual rules use `"on"` or `"off"`.

The enabled rules set the PHPStan level Pun analyses at: the highest level of a core rule that is on, or of a preset type switch. `stubs`, `[[analyse.ignore]]` and the rule options `pun migrate` writes apply as PHPStan's `stubFiles`, `ignoreErrors` and parameters do. An ignore entry nothing matched is an error, with PHPStan's message. Larastan's knowledge and rules are on when composer.lock pins a Laravel that Larastan 3 supports (11.44.2 and later 11.x, 12.4.1 and later 12.x, 13.x).

With every analyse rule off, `pun analyse` stops with "No rules detected", as PHPStan does without a level, and exits 2.

## Rule names

Human output uses Pun IDs such as `analyse/undefined/function`. Machine reports retain PHPStan identifiers such as `function.notFound`.

Static calls check PHPDoc `@method` signatures, including inherited tags. Pun checks their required and named arguments and reports static calls to non-static methods.

Static property checks resolve each name in a finite inferred name set.
Failed reads retain PHPStan's error type rather than `null`.
Property increment and decrement checks validate the stored new value separately from a postfix expression's old result.

Failed named instance and static method lookups retain PHPStan's error type when no reflected or provider result exists.
Ordinary method calls retain unknown-class diagnostics and their discovery tips. Dynamic selectors and `method_exists()` assertions retain their separate fallback behavior.

Unresolved named function calls retain PHPStan's error type after argument evaluation, including inside `function_exists()` guards.
Dynamic callable result inference remains incomplete.

Inherited PHPStan API signatures resolve PHPDoc names using the embedded declaration's namespace and imports.

Argument-count checks distinguish empty arrays from non-empty open array shapes passed with `...`.

When argument type checks are enabled, calls respect `@no-named-arguments` on functions, methods and constructors, including inherited policies. Named arguments and string-keyed unpacking produce PHPStan's `argument.named` diagnostic after argument binding. Unknown arguments retain their binding diagnostics.

At PHPStan level 5 and above, shared argument checks validate allowed built-in constants and report unresolvable generic parameter types.
Unresolvable-type diagnostics preserve the explanation from the type comparison or deferred array-shape key.
Shared argument checks also reject static closures for parameters that require a bound `$this`.
These checks also apply to attribute constructors.

Shared attribute checks preserve explicit import aliases and evaluate parenthesized flag expressions.
Global constant reflection keeps initializer unions separate from file-local flow values.
Deferred global references resolve before ternary and null-coalescing filtering.
Loaded class and interface constants also retain canonical initializer unions separately from declared types.
Named, `self` and `parent` dependencies resolve in the declaring class's scope before ternary and null-coalescing filtering.
Trait constants use the selected implementing class's scope. Inherited non-private constants retain that identity even when a subclass explicitly reuses the trait.
Trait constant conflicts compare complete initializer unions and array shapes.
Unsupported initializer expressions retain `mixed` in reflection, including trait conflicts and nested arrays. Ordinary calls retain their flow-inferred types.
Initializer coalescing removes explicit `null` alternatives without subtracting `null` from `mixed`.
Named `new` initializers retain bare class identities without constructor-inferred generic arguments. Member lookups use template defaults and bounds without changing those identities.
Expression-class initializers such as `new (Box::class)(1)` retain `object`. Ordinary construction still infers constructor arguments.
Finite class-string and object initializer holders resolve named constants across their possible classes, including forward and scanned dependencies.
Exact class strings retain raw initializers. Object holders respect final classes and native or PHPDoc declarations.
Canonical joins preserve reflection order, including the first mixed or error value. Trait constant equality ignores union member order within values.
Reflected initializer magic constants use PHPStan's reflection context. Ordinary trait declaration and attribute checks use the consuming class's scope.
Named class-constant reads preserve keyed initializer array order. General mixed and spread array ordering, expanded initializer cycles and dynamic initializer selectors remain incomplete.
Trait constructors retain adapted visibility, named-argument policies and parameter types in the consuming class's scope.
Constructor template checks use the reflected return type, including implicit `void`, rather than the raw `@return` tag.
Attribute rule support remains incomplete.

`__COMPILER_HALT_OFFSET__` requires a parsed top-level `__halt_compiler()` statement.
Occurrences inside comments, strings or inline HTML do not define it.

Shared class-name checks honor `checkInternalClassCaseSensitivity` and `featureToggles.checkImportedClassNameCase` from PHPStan configuration.
Both default to false; bleeding-edge configuration enables imported-name checking unless explicitly disabled.

Source `class_alias()` calls do not register aliases during analysis or scanning.
Laravel's statically resolved alias registry remains available.

Invalid reserved or qualified special class names and duplicate imports report non-ignorable parser diagnostics.
Invalid class or member modifiers, variadic defaults and direct `void` parameters also report parser diagnostics.
Parser checks reject `try` without a catch or finally, unknown property hooks, explicit getter parameter lists and empty hook lists.
Braced namespaces cannot contain direct nested namespace declarations.
Namespace checks reject mixed declaration styles, misplaced namespace declarations and code outside braced namespaces.
Attributes cannot annotate multiple global constants in one declaration.
PHP opening tags inside leading shebang text remain visible to analysis and symbol scanning.
An unmatched `}` at PHP compilation-unit entry reports a parser error and rejects declarations after it.
PHP 8.5 targets require parentheses around an arrow function used directly on the right-hand side of `|>`.
Assignments such as `$value =& new Thing()` report a parser error at the assignment's start.
Trailing commas in `for` clauses and echo lists report a parser error at the comma, including short echo tags.
Empty array elements report parser errors after namespace checks. Parser checks permit omitted destructuring targets, including nested array targets.
Named classes and direct anonymous-class expressions respect pre-8.1 `readonly` tokenization.
Heredoc and nowdoc closing markers cannot mix tabs and spaces, regardless of the configured PHP target version.
Document bodies validate indentation before escape decoding.
Fatal Unicode escape errors stop later parser reductions; malformed escapes remain nonfatal.
Parser diagnostic locations preserve PHP's string-escape newline accounting.
Malformed legacy octals such as `08` report PHPStan's non-ignorable `Invalid numeric literal` error over the complete literal.
Analysis preserves PHP's overflowing-octal-prefix float classification. Lint and format keep strict PHP syntax checks.
Invalid files contribute no scanned symbols; command output contains only the severe parser errors.
General PHP syntax-error translation remains incomplete.

Assignment checks allow references on individual destructuring targets and nested `array(...)` targets inside short-array destructuring.
Arrays nested directly inside an explicit `list()` remain literal expressions, not destructuring targets.
Their keys and values are read after the right-hand side and preceding targets, including reference-item values.

The `compact()` check preserves resolved function-import names and reads variable certainty before evaluating arguments.
Benevolent unions and callable-array intersections retain their literal variable names.
Its findings share `analyse/undefined/variable` selection; independent compact-rule selection remains incomplete.
Nested variable names are checked as reads even when assignment, `isset`, `empty`, coalescing or `unset` permits an undefined outer target.
Variable-name type errors point to the name expression's line, including multiline names.
Variable names read from literal array offsets retain branch-dependent definedness after direct offset assignments.
Writes to the array or another offset invalidate those cached names.
Literal string offsets use PHP bytes and support negative integer indexes.

Shared scope inference honors PHPStan's `polluteScopeWithLoopInitialAssignments` parameter, which defaults to true.
When disabled, `for` exits include the pre-loop scope; `while` adds that scope only when zero iterations are possible.
The setting does not change `checkMaybeUndefinedVariables`, `foreach`, or `do-while` behavior.

Dynamic `new $class` expressions report unknown class names even when another possible name exists.

Dynamic constant fetches such as `Example::{$name}` check each possible name when the selector has a finite set of string values. The checks preserve branch narrowing and report missing or inaccessible constants.

Class-constant checks retain expression guards across branches, ternaries and short-circuit conditions.
Writes invalidate guards for the affected receiver or selector.
Named calls retain their argument identities; impure methods and by-reference arguments invalidate affected guards.
Dynamic method selectors retain their written expression identities, including PHPStan's distinction between instance and static literal selectors.
Dynamic function and nullsafe calls, indirect variables, dynamic property selectors and general type-dependent comparisons remain unsupported.

Inline non-static closures and arrow functions use the class named by `@param-closure-this`.
Pun resolves these tags on named functions and methods called through a class name or a single known object class, including nullable receivers.
Bindings from multiple possible receiver classes remain unsupported.

`PHPStan\dumpType()` reports inferred types in PHPStan's precise diagnostic notation. `PHPStan\dumpPhpDocType()` reports the same types as PHPDoc. Each argument produces one non-ignorable diagnostic on the call's line. Native type dumps, scope dumps, and the `PHPStan\Testing` assertion functions remain unported.

Constant-bound templates retain their identities when combined with literal scalar types.
Union descriptions use PHPStan's ordering, including distinct null-bound templates.
Type compatibility treats `NAN` as equal to `NAN`, and `0.0` as equal to `-0.0`, including inside array shapes.

At level 9, receiver checks also validate explicitly declared `mixed`.
At level 10, they also validate implicit `mixed`.
These checks preserve template bounds and defaults in diagnostics without changing inferred types.
Static calls and first-class callables through `class-string<stdClass>` report non-object method errors; `class-string<mixed>` remains unchecked.
Argument checks preserve declared `mixed` inside generic types and callable signatures.
Generic callable arguments specialize their own templates before comparison; generic class arguments respect declared covariance and contravariance.
First-class generic callbacks retain conditional returns until their expected input types are known.

Negative type guards preserve excluded values in `mixed` types.
Object intersections discard duplicate constraints without losing generic arguments or `static` identity.
Union method reflection preserves member order when choosing the declaring class; printed type descriptions remain sorted.
Generic type comparisons treat differently ordered union and intersection members as equal.
Shared analysis retains exact instantiated-class alternatives without marking their class declarations final.
Conversion to Pun's PHPStan object types does not yet retain that exactness.
Short-circuit boolean expressions retain evaluated operand types and their excluded object alternatives.
Output arguments evaluated only on a short-circuited right operand remain possibly undefined on paths that skip that operand.
Full type inference preserves explicit `mixed` from native and PHPDoc declarations, built-in return types, assignments and captures.
Mixed offset reads keep explicitness but drop receiver truthiness and exclusions.
Unknown properties and methods remain implicit `mixed`.
`clone` results retain only object alternatives; cloning `$this` produces `static`.
Only declared or inherited assertion contracts narrow a caller's arguments; a predicate inferred from a callee's body does not.
Native `unset` checks retain a property's modifiers and hooks beneath a PHPDoc property annotation.
Annotation-only properties do not acquire native modifiers.
Interface `@phpstan-require-extends` properties participate in native unset checks, preserving annotation-only reflections as non-native.
Property writes use the reflected writable type, including compatible PHPDoc annotations over native properties.

`array_rand()` inference preserves possible array keys and returns a non-empty list when the requested count is at least two.
`rand()`, `mt_rand()` and `random_int()` preserve inferred integer bounds.
Reversed bounds are swapped only for `rand()`, matching PHPStan.

PHPDoc union lowering preserves literal alternatives and nullable boundaries without recursive stack growth over flat unions.
Parsing and nested non-union types retain their existing stack limits.
The PHPStan-compatible PHPDoc resolver preserves decoded quoted array-shape keys as bytes, including through template substitution.
Quoted shape-key decoding in shared inference and non-UTF-8 identifier handling remain incomplete.

`strlen()` inference uses PHP scalar casts and byte lengths, including binary strings.
Literal alternatives produce exact lengths or a contiguous integer range. General integer ranges are not enumerated.
Stored callable signatures retain the declared return type rather than specializing it from invocation arguments.

`str_repeat()` inference returns exact literal alternatives when their combined output occupies fewer than 100 bytes.
Larger or unknown results retain PHPStan's applicable string refinements, including simultaneous lowercase and uppercase guarantees.
Constant strings preserve binary bytes through PHPDoc decoding and type comparisons.
String unions retain incomparable refinements, such as `lowercase-string|uppercase-string`, rather than widening them to `string`.
Numeric strings are nonempty, but retain an independent `non-empty-string` refinement only when that refinement is present in the inferred type.
Concatenating two definitely nonempty strings produces `non-falsy-string`.
Repeating an unknown nonempty string twice retains only `non-empty-string`, matching PHPStan's separate repeat inference.

Integer and IP validation through `filter_input()` and `filter_var()` preserves failure values, array flags, defaults and integer range options.
Other filters and `FILTER_THROW_ON_FAILURE` retain declaration-based inference.

Implicit `never` from an empty value domain does not make later statements unreachable.
Call termination follows the resolved declaration, separately from a dynamic return type.
An expression statement whose value is explicit `never` also terminates, matching PHPStan's treatment of forwarded calls.
`exit`, `die`, and `throw` produce PHPStan's nonaccepting `never`, including through inferred arrow-function returns.

From level 2, `analyse/functions/invalid-pure` reports `void.pure` for supported functions and private methods whose bodies provably have no side effects.
Unknown effect producers remain unchecked. Full pure-function and pure-method validation remains incomplete.

Array writes distinguish definite literal keys from literal alternatives within a general string or integer key.
A false `isset` probe leaves the array unchanged when its nullable entry might be absent.
A required nullable entry narrows to `null`.
`foreach` loops over sealed constant lists of up to 16 required entries retain sequential array mutation state, including local `continue` edges.
Nested replay applies PHPStan's product limit of eight once an outer replay has more than one entry.
References, `break`, `return`, optional entries, shape unions, associative iterators, and non-direct targets retain general loop inference.

An [ignore comment](/docs/configuration/ignore-comments) suppresses a matching ignorable finding:

```php
legacy_hook(); // @pun-ignore analyse/undefined/function -- provided at runtime
```

## Files

Path arguments replace `[analyse] paths`, which otherwise defaults to `[files] paths` or the project root. Analysis skips Blade templates, `vendor/`, `bootstrap/cache`, `build`, `node_modules`, and `storage`.

`[analyse] exclude` removes matching files from analysis and the symbol scan. Pun still reads Composer dependencies for symbols. [`pun list-files --command analyse`](/docs/commands/list-files) shows the analysed files.

Include-path checks recognize local files, `file://` URLs, and local `phar://` members in native PHAR, ZIP, TAR, and gzip-compressed archives.
These checks model PHP's default `phar.require_hash=1`, with gzip but not bzip2.
Runtime-registered wrappers, PHAR aliases and mounts, and OpenSSL signatures remain unsupported.
PHP's `zip://` wrapper cannot answer file-existence checks, so it still reports a missing file.

## Baseline

```bash
pun analyse --generate-baseline
```

This writes to `[analyse] baseline`, or `pun-baseline.toml` when unset, and exits 0. An optional path selects another file: `pun analyse --generate-baseline old.toml`.

Configure the file to suppress its findings on later runs:

```toml
[analyse]
baseline = "pun-baseline.toml"
```

Entries match by file, rule, message, and count, not line number. Pun notes entries that no longer match. PHPStan baselines are not read or copied.

Errors PHPStan marks as non-ignorable, such as a duplicate parameter, remain visible even when an ignore comment or baseline entry matches. Baseline generation omits these errors. JSON reports identify them with `"ignorable": false`.

## Output and exit codes

Default output includes code frames and a summary. `--concise` prints one line per finding. `--max-processes` caps worker threads.

`--format`, also spelled `--error-format`, selects a PHPStan-compatible report: `table`, `raw`, `json`, `prettyJson`, `checkstyle`, `junit`, `gitlab`, `github`, or `teamcity`. `-v` adds identifiers to `raw` output.

Exit code 0 means no errors, 1 means errors, and 2 means Pun could not run.
