---
title: pun analyse
description: Report type errors with the same results as PHPStan and Larastan, including baselines and ignores. It never edits files.
---

```bash
pun analyse          # alias: pun analyze
pun analyse app tests
```

`pun analyse` reports the same errors as PHPStan with Larastan, honours your baseline and ignores, and never edits a file. Larastan's Laravel knowledge (models, relations, facades, container bindings, config) is built in.

## Configuration

`pun migrate` writes this from your `phpstan.neon`:

```toml pun.toml
[analyse]
preset = "strict"
paths = ["app", "tests"]
baseline = "pun-baseline.toml"

[analyse.rules]
"types/missing-return-type" = "off"
```

There are no levels. An [analyse preset](/docs/configuration/presets#analyse-presets) picks PHPStan's levels in five bands, and rules turn on and off one by one. `pun migrate` expands your PHPStan level into the exact list of rules it ran, so nothing changes on migration day.

## Rule names

Errors carry Pun's own IDs, `analyse/<group>/<name>`: `analyse/undefined/method` rather than `method.notFound`. Silence one with an [ignore comment](/docs/configuration/ignore-comments):

```php
$user->fullName(); // @pun-ignore analyse/undefined/method -- added by a macro
```

## Files

`pun analyse` checks `[analyse] paths` (else `[files] paths`, else the project) or the paths you give it, without Blade templates and Pint's default directories (`bootstrap/cache`, `build`, `node_modules`, `storage`). `[analyse] exclude` globs drop files from the analysis and from the symbol scan, like PHPStan's `excludePaths`.

## Baseline

```bash
pun analyse --generate-baseline              # [analyse] baseline, else pun-baseline.toml
pun analyse --generate-baseline old.toml
```

The baseline lists each file's errors by rule and message with a count, so an error that moves to another line stays covered. A run with `[analyse] baseline` drops the errors it lists and notes entries that no longer match. A PHPStan baseline is never read; `pun migrate` asks you to generate a new one.

## Output and exit codes

Humans get code frames and a summary line; `--concise` prints one line per error. `--format` (alias `--error-format`) prints PHPStan's formats byte for byte: `table`, `raw`, `json`, `prettyJson`, `checkstyle`, `junit`, `gitlab`, `github` and `teamcity`, with PHPStan's identifiers (`method.notFound`); `-v` adds them to `raw`. Under GitHub Actions the human output is followed by one annotation per error.

`pun analyse` exits 0 without errors, 1 with errors, and 2 when Pun couldn't run (a bad `pun.toml` or baseline, an unknown format, an unreadable file). `--max-processes` caps the threads.
