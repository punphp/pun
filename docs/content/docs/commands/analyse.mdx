---
title: pun analyse
description: Report type errors without editing files. PHPStan and Larastan support is incomplete.
---

```bash
pun analyse
pun analyse app tests
```

`pun analyze` is an alias. The [rule reference](/docs/rules/analyse) lists implemented and Planned checks. Pun does not yet replace every PHPStan or Larastan check.

## Configuration

```toml pun.toml
[analyse]
preset = "strict"
paths = ["app", "tests"]

[analyse.rules]
"types/missing-return-type" = "off"
```

The five [analyse presets](/docs/configuration/presets#analyse-presets) group PHPStan levels. Individual rules use `"on"` or `"off"`.

The enabled rules set the PHPStan level Pun analyses at: the highest level of a core rule that is on, or of a preset type switch. `stubs`, `[[analyse.ignore]]` and the rule options `pun migrate` writes apply as PHPStan's `stubFiles`, `ignoreErrors` and parameters do. An ignore entry nothing matched is an error, with PHPStan's message. Larastan's knowledge and rules are on when composer.lock pins a Laravel that Larastan 3 supports (11.44.2 and later 11.x, 12.4.1 and later 12.x, 13.x).

With every analyse rule off, `pun analyse` stops with "No rules detected", as PHPStan does without a level, and exits 2.

## Rule names

Human output uses Pun IDs such as `analyse/undefined/function`. Machine reports retain PHPStan identifiers such as `function.notFound`.

Static calls check PHPDoc `@method` signatures, including inherited tags. Pun checks their required and named arguments and reports static calls to non-static methods.

Dynamic `new $class` expressions report unknown class names even when another possible name exists.

Dynamic constant fetches such as `Example::{$name}` check each possible name when the selector has a finite set of string values. The checks preserve branch narrowing and report missing or inaccessible constants.

Inline non-static closures and arrow functions use the class named by `@param-closure-this`.
Pun resolves these tags on named functions and methods called through a class name or a single known object class, including nullable receivers.
Bindings from multiple possible receiver classes remain unsupported.

`PHPStan\dumpType()` reports inferred types in PHPStan's precise diagnostic notation. `PHPStan\dumpPhpDocType()` reports the same types as PHPDoc. Each argument produces one non-ignorable diagnostic on the call's line. Native type dumps, scope dumps, and the `PHPStan\Testing` assertion functions remain unported.

An [ignore comment](/docs/configuration/ignore-comments) suppresses a matching ignorable finding:

```php
legacy_hook(); // @pun-ignore analyse/undefined/function -- provided at runtime
```

## Files

Path arguments replace `[analyse] paths`, which otherwise defaults to `[files] paths` or the project root. Analysis skips Blade templates, `vendor/`, `bootstrap/cache`, `build`, `node_modules`, and `storage`.

`[analyse] exclude` removes matching files from analysis and the symbol scan. Pun still reads Composer dependencies for symbols. [`pun list-files --command analyse`](/docs/commands/list-files) shows the analysed files.

## Baseline

```bash
pun analyse --generate-baseline
```

This writes to `[analyse] baseline`, or `pun-baseline.toml` when unset, and exits 0. An optional path selects another file: `pun analyse --generate-baseline old.toml`.

Configure the file to suppress its findings on later runs:

```toml
[analyse]
baseline = "pun-baseline.toml"
```

Entries match by file, rule, message, and count, not line number. Pun notes entries that no longer match. PHPStan baselines are not read or copied.

Errors PHPStan marks as non-ignorable, such as a duplicate parameter, remain visible even when an ignore comment or baseline entry matches. Baseline generation omits these errors. JSON reports identify them with `"ignorable": false`.

## Output and exit codes

Default output includes code frames and a summary. `--concise` prints one line per finding. `--max-processes` caps worker threads.

`--format`, also spelled `--error-format`, selects a PHPStan-compatible report: `table`, `raw`, `json`, `prettyJson`, `checkstyle`, `junit`, `gitlab`, `github`, or `teamcity`. `-v` adds identifiers to `raw` output.

Exit code 0 means no errors, 1 means errors, and 2 means Pun could not run.
