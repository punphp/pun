---
title: pun init
description: Write pun.toml for a new project by answering three questions, or take the defaults with --yes.
---

```bash
pun init                                                  # on a terminal: three questions
pun init --yes                                            # the defaults, no questions
pun init --style psr12 --lint-sets dead-code,types --analyse strict
```

`pun init` is for a project with no Pint, PHP-CS-Fixer, PHPStan, Rector or Mago config yet. A project that has one
runs [`pun migrate`](/docs/commands/migrate) instead.

## The flow

```text
$ pun init

  Pun · new project setup
  Found Laravel 13, Pest 4, PHP ^8.4 (composer.json, composer.lock)

✔ Code style · laravel
✔ Lint sets (space toggles, enter confirms) · dead-code, modernize
✔ Analysis preset · recommended

  Laravel, Pest and PHPUnit rules turn on by themselves (composer.lock).

  ✔ Wrote pun.toml

  Done. Run `pun check` any time; `pun check --fix` before you commit.
  Add `pun check` to CI and your composer scripts.
```

1. **Detect.** composer.json gives the PHP constraint; composer.lock gives the Laravel, Pest and PHPUnit versions.
2. **Ask three questions** (`? Code style ›` while asking, `✔ Code style · laravel` once answered), each starting on
   a default that fits the project:

   | Question | Choices | Default | Flag |
   | --- | --- | --- | --- |
   | Code style (`[format] preset`) | `laravel`, `psr12` | `laravel` for a Laravel app, else `psr12` | `--style` |
   | Lint sets (`[lint] sets`) | `dead-code`, `modernize`, `code-quality`, `types`, `early-return`, `privatization`, `naming`, `coding-style` | `dead-code`, `modernize` | `--lint-sets a,b` (`""` for none) |
   | Analysis preset (`[analyse] preset`) | `basic`, `essential`, `recommended`, `strict`, `max` | `recommended` | `--analyse` |

   `empty` is not offered, but stays a valid `[format] preset` in pun.toml.
3. **Write pun.toml** with only those three choices. The presets and sets carry the rules; `pun config` prints the
   resolved list. Laravel, Pest and PHPUnit rules need no setting: they follow composer.lock.

```toml
# Written by `pun init`.
[format]
preset = "laravel"

[lint]
sets = ["dead-code", "modernize"]

[analyse]
preset = "recommended"
```

`pun init` never writes composer scripts, CI files, git hooks or editor settings. It prints the commands to add.

## Without a terminal

With `--yes`, under a [coding agent](/docs/guides/coding-agents), with `CI` set, or when stdin or stdout is not a
terminal, nothing is asked: the defaults or the flags are used and the next steps are printed, not run. An unknown
set or preset stops the run with exit code 2 and names the valid ones.

## Existing configs

- **pun.toml exists:** `pun init` never overwrites it. It exits 2 and leaves the file as it was.
- **pint.json, .php-cs-fixer.php, phpstan.neon, rector.php or mago.toml found:** on a terminal, `pun init` asks
  "Found pint.json. Migrate it instead?" (default yes). Yes runs `pun migrate`; no goes on with the questions. Without
  a terminal it writes nothing, says that `pun migrate` fits the project, and exits 2.

## Exit codes

| Code | When |
| --- | --- |
| 0 | pun.toml written, or `pun migrate` ran and succeeded |
| 2 | pun.toml exists, an old config points to `pun migrate` (without a terminal), or a flag is invalid |
