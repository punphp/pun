---
title: pun init
description: Create pun.toml for a project without existing tool configs.
---

```bash
pun init
pun init --yes
pun init --style psr12 --lint-sets dead-code,types --analyse strict
```

For an existing Pint, PHP-CS-Fixer, PHPStan, Rector, or Mago config, use [`pun migrate`](/docs/commands/migrate).

## Choices and defaults

On a terminal, `pun init` asks three questions:

| Setting | Choices | Default | Flag |
| --- | --- | --- | --- |
| Format preset | `laravel`, `psr12` | `laravel` when detected, otherwise `psr12` | `--style` |
| Lint sets | The eight [lint sets](/docs/configuration/presets#lint-sets) | `dead-code`, `modernize` | `--lint-sets a,b` |
| Analyse preset | `basic`, `essential`, `recommended`, `strict`, `max` | `recommended` | `--analyse` |

`--lint-sets ""` selects no lint sets. The `empty` format preset is valid in `pun.toml` but is not an init choice.

Pun reads the PHP constraint from `composer.json` and ecosystem versions from `composer.lock`. The generated config contains only the three choices:

```toml
[format]
preset = "laravel"

[lint]
sets = ["dead-code", "modernize"]

[analyse]
preset = "recommended"
```

Init prints next steps but does not run checks, apply fixes, or generate a baseline. It does not edit Composer scripts, CI, Git hooks, or editor settings.

## Without a terminal

`--yes`, agent mode, `CI`, or a non-terminal input or output disables prompts. Pun uses defaults and explicit flags.

## Existing configs

- If `pun.toml` exists, init leaves it unchanged and exits 2.
- If an upstream config exists, interactive init offers migration. Without prompts, it writes nothing and exits 2 with a migration hint.

## Exit codes

| Code | When |
| --- | --- |
| 0 | Configuration written or migration succeeded |
| 2 | Existing config, invalid flag, or another run error |
