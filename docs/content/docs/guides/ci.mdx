title: CI
description: Check a project without edits and publish CI reports.
---

Run [`pun check`](/docs/commands/check) without `--fix`. It reports formatting changes, lint errors, and analysis errors without editing files.

## GitHub Actions

Add this step after your usual PHP setup and `composer install`, which installs Pun from your `require-dev` (see [installation](/docs/installation)).

```yaml .github/workflows/style.yml
- name: Check
  run: vendor/bin/pun check
```

Under `GITHUB_ACTIONS=true`, Pun adds annotations to its default output. `pun check --format=github` prints annotations only.

## Report files

For a formatting-only check with a Checkstyle report:

```bash
pun format --test --output-to-file=pun.xml --output-format=checkstyle
```

`--output-format` also accepts `junit`, `gitlab`, `json`, `xml`, and `txt`.

## Pre-commit hook

Use `pun check --staged` to select files with staged changes. Pun reads working-tree contents, including unstaged edits in those files.

Exit code 0 means clean, 1 means findings, and 2 means Pun could not run. Warnings fail only with `--deny-warnings` or when they exceed `--max-warnings`.
