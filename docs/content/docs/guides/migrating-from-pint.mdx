---
title: Migrating from Pint
description: Switch a project from Pint to Pun without a single changed byte, then move scripts and CI over.
---

<Steps>
  <Step title="Write pun.toml">

```bash
pun migrate --dry-run
pun migrate
```

Reads `pint.json` and writes `pun.toml`. Risky rules your `pint.json` enabled move to `[lint.rules]` at `"error"`.

  </Step>
  <Step title="Prove nothing changes">

```bash
pun check --fix
git diff --stat
```

On a project Pint already formatted, the diff is empty: `pun check --fix` writes exactly what `pint` wrote.

  </Step>
  <Step title="Switch your scripts">

```json composer.json
{
  "scripts": {
    "lint": "pun check --fix",
    "test:lint": "pun check"
  }
}
```

  </Step>
  <Step title="Switch CI">

Replace `vendor/bin/pint --test` with `pun check` ([CI](/docs/guides/ci)).

  </Step>
</Steps>

## What moved where

`pint` did two kinds of thing in one run: layout, and rewrites that change code, like making classes `final`, comparisons strict, or removing unused imports and superfluous PHPDoc tags. Pun splits them: the rewrites are lint rules. `pun format` runs layout only, which is what format-on-save should do. `pun check --fix` runs both, like `pint` did.

:::tip[Rolling back]
Your code doesn't change, and `pint.json` stays unless you pass `--remove-tools`. Switching back is reverting the script and CI lines.
:::
