Pun's formatter is compared with Pint 1.29.3 and PHP-CS-Fixer 3.95.17. The results below are recorded runs, not a guarantee for every configuration.

PHPStan, Larastan, and Rector support is incomplete. A mapped rule is not necessarily implemented. The [rule reference](/docs/rules) marks unimplemented rules as Planned.

## Laravel class aliases

When Laravel analysis is enabled, Pun reads class aliases without running PHP. The alias sources are:

- The installed framework's `Facade::defaultAliases()` and default application config.
- A literal `aliases` array in `config/app.php`, or the standard `defaultAliases()->merge([...])->toArray()` expression. A replacement array does not retain the defaults.
- `app.aliases` in `bootstrap/cache/config.php`, when that cache exists. The cache replaces the source config.
- `bootstrap/cache/packages.php`, or package aliases in `vendor/composer/installed.json` when the manifest is absent. Package discovery respects the application's and packages' `dont-discover` lists.

Package aliases override application aliases. An imported global `Blade` alias denotes `Illuminate\Support\Facades\Blade`, not the container's Blade compiler. Without an import, `Blade` inside `namespace App` refers to `App\Blade`. A global alias does not define that class.

Alias identity does not add method forwarding to container services. Pun does not execute service providers, dynamic config expressions, or programmatic `AliasLoader` changes. Custom bootstrap, config, cache, and vendor paths, and real-time `Facades\...` classes are not supported by this alias reader.

An exact-spelling reference activates its alias throughout Pun's order-independent symbol graph. Unlike PHPStan, Pun does not model a differently cased lookup before that reference. Known class declarations win. Runtime load-order collisions, including differently cased aliases with different targets, are not simulated.

## Speed

The 2026-10-16 benchmark used a profiling build on a shared 2-core, 7 GB machine. These are median wall times from three runs on laravel/framework:

| | Time |
| --- | --- |
| Pint | 190 s |
| Pun, cold | 3.7 s |
| Pun, warm cache | 0.07 s |

Cold runs disable Pun's cache. Warm runs use a clean tree with cached results. Pint does not cache in this comparison. These timings are not measurements of the current checkout.

## Byte-for-byte output

The harness runs Pint on one project copy and `pun migrate` followed by `pun check --fix` on another. It then compares each file. The recorded results are:

| Project | Files | Identical | Differing |
| --- | --- | --- | --- |
| larastan | 725 | 725 | 0 |
| laravel/framework | 3,483 | 3,483 | 0 |
| laravel/laravel | 66 | 66 | 0 |
| laravel/pint | 573 | 573 | 0 |
| pest | 757 | 757 | 0 |
| pinkary | 799 | 799 | 0 |
| pinkary (unformatted copy) | 799 | 799 | 0 |

`scripts/cli-parity.sh` compares exit codes, machine reports, and changed files. Pun deliberately exits 2 when it cannot run, where Pint exits 1.

Pinkary appears twice: as committed and as an unformatted copy where Pint changes 346 files. The report also records zero differing files for the `psr12` preset.

## Fuzzing

`scripts/fuzz-parity.sh` mutates style in real PHP files, formats copies with both tools, and compares the results. The report includes seeded runs on Pinkary and laravel/framework, plus CRLF and mixed-line-ending cases.

## Reproduce a comparison

From the repository root:

```bash
scripts/oracle.sh
scripts/corpus.sh pinkary
cargo run -p punphp-harness -- format --corpus pinkary --diffs 5
```

The [scoreboard](https://github.com/punphp/pun/blob/main/context/reports/scoreboard.md) records the full results, commands, and benchmark conditions.
