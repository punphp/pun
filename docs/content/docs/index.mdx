Pun is one very fast binary, written in Rust, for your whole PHP workflow. Our goal is a unified toolchain that stays compatible with the tools PHP projects use today: Pint and PHP-CS-Fixer, Rector, PHPStan and Larastan, and Composer. Each Pun command gives the same answers as the tool it replaces, so you can switch one command at a time.

Pun supports projects that target PHP 8.4 or later. Supporting current PHP only lets every command match its upstream tool exactly, instead of approximating behaviour across older versions.

## Commands

| Command | What it does |
| --- | --- |
| [`pun format`](/docs/commands/format) | Fixes layout, casing, and spelling, as Pint and PHP-CS-Fixer do |
| [`pun lint`](/docs/commands/lint) | Reports code issues and fixes them with `--fix`, as Rector, Mago, and PHP-CS-Fixer's risky fixers do |
| [`pun analyse`](/docs/commands/analyse) | Reports type errors without editing files, as PHPStan and Larastan do |
| [`pun check`](/docs/commands/check) | Runs format, lint, and analyse in one pass |
| [`pun migrate`](/docs/commands/migrate) | Converts your Pint, PHP-CS-Fixer, Rector, and PHPStan configs to `pun.toml` |
| [`pun init`](/docs/commands/init) | Creates `pun.toml` for a new project |
| [`pun install`](/docs/commands/install) | Installs the locked dependencies into `vendor/`, with the same files Composer writes |
| [`pun self-update`](/docs/commands/self-update) | Replaces `pun` with the latest release |

## Status

- **Format** matches Pint byte for byte on every project in the [parity scoreboard](/docs/parity). It changes layout only. Pint's risky and code-deleting fixers are lint rules, so a migrated Pint configuration uses `pun check --fix`.
- **Lint** and **analyse** are previews. PHPStan, Larastan, and Rector support is incomplete; the [rule reference](/docs/rules) marks rules that are not ported yet as Planned.
- **The package manager** installs from a lock and writes the `vendor/` tree Composer writes. Choosing versions (`pun update`, `pun require`) is in progress, so `composer update` still creates the lock.

PHP checks need no PHP runtime. Blade formatting requires Node.js (or Bun) and Prettier. Some config migrations require PHP and the original tool.

## Get started

[Install Pun](/docs/installation), then run these commands from your project root.

<Steps>
  <Step title="Create pun.toml">

If you have a Pint, PHP-CS-Fixer, Rector, or PHPStan config, start from a clean Git working tree. Migration can rewrite ignore comments in PHP files. Preview and run the migration:

```bash
pun migrate --dry-run
pun migrate
```

Review warnings about unsupported items. Migration skips those items and writes the supported configuration.

For a project without tool configs, use:

```bash
pun init
```

Both commands write `pun.toml`. Neither changes your scripts or CI configuration.

  </Step>
  <Step title="Check the project">

```bash
pun check
```

Pun reports format, lint, and analysis findings without editing files. Exit code 0 means clean, 1 means findings, and 2 means Pun could not run.

  </Step>
  <Step title="Apply fixes">

```bash
pun check --fix
git diff
```

Review the format and lint changes. Analysis never edits files, and lint rules with `fix = "off"` remain report-only.

  </Step>
  <Step title="Check changed files">

```bash
pun check --dirty
pun check --staged
pun format --diff=main
```

`--dirty` selects uncommitted changes. `--staged` selects files with staged changes. `--diff=main` selects files changed since branching from `main`.

  </Step>
</Steps>
