Pun is to PHP what Bun is to JavaScript: one install that replaces the pile of tools a Laravel project runs on every commit. It formats like Pint, refactors like Rector and analyses like PHPStan and Larastan, from one `pun.toml`, in one process.

![The Pun mascot, sprinting](/mascot-512.png)

## Why Pun

A Laravel project runs four or five PHP tools on every commit. Each one is slow (Pint takes 190 s on laravel/framework), has its own config format, rule names and ignore comments, overlaps with the others, and prints for humans while coding agents pay for every token.

Pun goes for **exact parity first**, so switching changes nothing: `pun migrate` writes your config once, and `pun check --fix` writes exactly what Pint wrote. Every command is checked against pinned versions of the real tools, their own test suites, real projects and a fuzzer. Then it gives you a better model: one config, one set of rule names, no levels.

## Commands

| Command | Does | Replaces |
| --- | --- | --- |
| [`pun format`](/docs/commands/format) | Fixes layout, byte for byte like Pint | Pint, PHP-CS-Fixer |
| [`pun lint`](/docs/commands/lint) | Reports and fixes code rules | Rector, Mago's linter |
| [`pun analyse`](/docs/commands/analyse) | Reports type errors | PHPStan, Larastan |
| [`pun check`](/docs/commands/check) | All three in one pass | `rector process && pint && phpstan` |
| [`pun migrate`](/docs/commands/migrate) | Moves a project onto `pun.toml` | Hand-editing configs |
| [`pun lsp`](/docs/commands/lsp) | Editor server | Format-on-save plugins, PHP language servers |

Under a coding agent, every command switches to compact `path:line:col rule message` output.

## Principles

- **Prove it.** Every speed and parity claim is checked against the real tool. See [Parity](/docs/parity).
- **No PHP or Node needed** to check a project.
- **Laravel first.** Larastan and rector-laravel behaviour are built in, not plugins.
- **PHP 8.4+.** Pun targets modern PHP and says so clearly on older projects.
