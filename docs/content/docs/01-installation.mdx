## Standalone installer

Every release from v0.1.0-beta.4 publishes an `install.sh`. It installs `pun` to `~/.pun/bin` without Composer or PHP:

```bash
version=0.1.0-beta.4
url=https://github.com/punphp/pun/releases/download/v$version
curl --proto '=https' --tlsv1.2 -sSf "$url/install.sh" | sh
```

The installer accepts HTTPS only, with TLS 1.2 or later, including on redirects. It installs only the archive its release was built with:

- The release workflow writes each archive's SHA-256 into `install.sh`. The installer refuses an archive whose checksum differs.
- When the GitHub CLI is installed and signed in, the installer also checks the archive's GitHub build attestation. The attestation proves that Pun's release workflow built the archive from the release tag.
- The installer refuses an archive with links or unexpected paths, and a binary that does not report the release's version.
- It never asks for `sudo` and does not edit your shell profile. If `~/.pun/bin` is not on your `PATH`, it prints the line to add.

To check the installer before it runs, download it, verify its attestation, and require the archive's attestation too:

```bash
curl --proto '=https' --tlsv1.2 -sSfO "$url/install.sh"
gh attestation verify install.sh --repo punphp/pun
PUN_REQUIRE_ATTESTATION=1 sh install.sh
```

Set `PUN_INSTALL` to install somewhere other than `~/.pun`; the binary goes in `$PUN_INSTALL/bin`. To update, run a newer release's installer. To uninstall, delete `~/.pun`.

## Composer

```bash
composer require --dev punphp/pun
vendor/bin/pun --version
```

The package is a small PHP script. On first run, it downloads the release binary for its version and platform (Linux or macOS, x86_64 or arm64) from GitHub Releases, checks its SHA-256 checksum, and keeps it in `vendor/bin`. Later runs start that binary directly. Windows is not supported.

These docs write commands as `pun`. In a project, run them as `vendor/bin/pun`, for example `vendor/bin/pun check`, or from a Composer script, where `vendor/bin` is on the `PATH`:

```json composer.json
"scripts": {
    "check": "pun check"
}
```

## Runtime requirements

- Projects must target PHP 8.4 or later. Pun reads the target from `composer.json` unless `[php] version` overrides it.
- PHP checks need no PHP or Node runtime.
- Blade formatting requires Node.js and these project dependencies. In a project with a `bun.lock` or `bun.lockb` file, Pun runs Prettier with Bun instead of Node.js. Prettier and its plugins are loaded from the project's `node_modules`, so Blade formatting runs project code.

```bash
npm install --save-dev prettier@^3.9.6 prettier-plugin-blade@^3.3.3 prettier-plugin-tailwindcss@^0.8.1
```

- In `*.blade.php` files, Pun does not run `no_unused_imports`, `fully_qualified_strict_types`, `global_namespace_import` or `declare_strict_types`, like Pint. These rules would corrupt the template's PHP blocks.

- Migrating `.php-cs-fixer.php` or `rector.php` requires PHP and the corresponding tool. For Rector, run `composer install` first.
