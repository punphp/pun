---
title: Quickstart
description: Move a Laravel project onto Pun in four commands, with zero changed bytes.
---

Pun reads one config file, `pun.toml`. `pun migrate` writes it from what you have today.

<Steps>
  <Step title="Migrate your config">

```bash
pun migrate --dry-run   # show the pun.toml it would write
pun migrate
```

Reads `pint.json` (or `.php-cs-fixer.php`), `phpstan.neon` and `rector.php`, and writes `pun.toml` with Pun's rule names. If a rule can't run, it says so and writes nothing.

  </Step>
  <Step title="Check everything">

```bash
pun check
```

Format, lint and analyse in one pass. Exits non-zero on any format diff, lint error or analyse error.

  </Step>
  <Step title="Fix what can be fixed">

```bash
pun check --fix
```

Formats and applies the lint fixes marked `fix = "apply"`. On a migrated project this writes exactly what `pint` wrote.

  </Step>
  <Step title="Only what you touched">

```bash
pun check --dirty        # uncommitted changes
pun check --staged       # staged changes, for a pre-commit hook
pun format --diff=main   # changed since branching off main
```

  </Step>
</Steps>

:::tip[Why is the second run so fast?]
Pun caches results per file under `~/.cache/pun`. On laravel/framework, `pun format` takes 3.7 s cold and 0.07 s warm. Use `--no-cache` to check every file.
:::
