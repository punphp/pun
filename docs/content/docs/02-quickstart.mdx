---
title: Quickstart
description: Create a configuration, check your project, and apply fixes.
---

Run these commands from your project root after [installing Pun](/docs/installation).

<Steps>
  <Step title="Create pun.toml">

If you have a Pint, PHP-CS-Fixer, Rector, or PHPStan config, start from a clean Git working tree. Migration can rewrite ignore comments in PHP files. Preview and run the migration:

```bash
pun migrate --dry-run
pun migrate
```

Review warnings about unsupported items. Migration skips those items and writes the supported configuration.

For a project without tool configs, use:

```bash
pun init
```

Both commands write `pun.toml`. Neither changes your scripts or CI configuration.

  </Step>
  <Step title="Check the project">

```bash
pun check
```

Pun reports format, lint, and analysis findings without editing files. Exit code 0 means clean, 1 means findings, and 2 means Pun could not run.

  </Step>
  <Step title="Apply fixes">

```bash
pun check --fix
git diff
```

Review the format and lint changes. Analysis never edits files, and lint rules with `fix = "off"` remain report-only.

  </Step>
  <Step title="Check changed files">

```bash
pun check --dirty
pun check --staged
pun format --diff=main
```

`--dirty` selects uncommitted changes. `--staged` selects files with staged changes. `--diff=main` selects files changed since branching from `main`.

  </Step>
</Steps>

See the [configuration reference](/docs/configuration/pun-toml) and [CI guide](/docs/guides/ci) for the remaining setup.
