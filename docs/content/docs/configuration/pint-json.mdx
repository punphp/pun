---
title: From pint.json
description: Configuration keys and rule names translated from Pint.
---

Pun commands read `pun.toml`, not `pint.json`. [`pun migrate --from pint`](/docs/commands/migrate) translates these settings:

| pint.json | pun.toml |
| --- | --- |
| `"preset": "laravel"` | `[format] preset = "laravel"` |
| `"rules"` that differ from the preset | `[format.rules]`, under Pun IDs and [option names](/docs/configuration/pun-toml#rule-options) |
| Risky and code-deleting rules | `[lint.rules]` at `"error"` |
| `"in"` | `[files] paths` |
| `"exclude"`, `"notName"`, `"notPath"` | `[format] exclude`, `not-name`, `not-path` |
| `"extend"` | Resolved the way Pint resolves it |
| `"Pun/prefer_fake_helper": true` | `[lint.rules] "laravel/prefer-fake-helper" = "error"` |

A `.php-cs-fixer.php` is read through PHP-CS-Fixer with system PHP. When both configs are selected, Pint takes precedence.

Pint's `per` and `symfony` presets expand into explicit rules over `preset = "empty"`. Rule options are translated to Pun names and values.

The [Pint rule mapping](/docs/migrate/from/pint) lists upstream names, translated options, and unsupported items. Skipped rules are reported during migration.

Use `pun check --fix` to apply both format and lint rules from a migrated config. The [migration guide](/docs/guides/migrating-from-pint) covers comparison and script changes.
