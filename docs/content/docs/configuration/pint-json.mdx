---
title: From pint.json
description: How pun migrate maps a pint.json onto pun.toml, rule by rule.
---

Pun doesn't read `pint.json` at run time. [`pun migrate`](/docs/commands/migrate) reads it once, the way Pint does, and writes `pun.toml`:

| pint.json | pun.toml |
| --- | --- |
| `"preset": "laravel"` | `[format] preset = "laravel"` |
| `"rules"` that differ from the preset | `[format.rules]`, under Pun IDs and [option names](/docs/configuration/pun-toml#rule-options) |
| Risky rules (`final_class`, `strict_comparison`, ...) | `[lint.rules]` at `"error"` |
| `"in"` | `[files] paths` |
| `"exclude"`, `"notName"`, `"notPath"` | `[format] exclude`, `not-name`, `not-path` |
| `"extend"` | Resolved the way Pint resolves it |
| `"Pun/prefer_fake_helper": true` | `[lint.rules] "laravel/prefer-fake-helper" = "error"` |

A `.php-cs-fixer.php` without a `pint.json` is read through PHP-CS-Fixer itself, so whatever it computes is what gets migrated.

```json pint.json
{
  "preset": "laravel",
  "rules": { "concat_space": { "spacing": "one" }, "final_class": true },
  "exclude": ["build"]
}
```

```toml pun.toml
[format]
preset = "laravel"
exclude = ["build"]

[format.rules]
"operators/concat-spacing" = "one"

[lint.rules]
# ...the laravel preset's 15 risky and code-deleting rules, each at "error", then:
"style/require-final-class" = "error"
```

`pun check --fix` on the migrated project writes exactly what `pint` wrote on the original.
