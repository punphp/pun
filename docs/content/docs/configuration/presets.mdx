Each command selects rules independently. There is no top-level preset.

## Format presets

| Preset | Rules |
| --- | --- |
| `laravel` | Pint's default layout rules; the default format preset |
| `psr12` | PSR-12 layout rules |
| `empty` | No rules unless explicitly enabled |

`[format.rules]` overrides the preset. Pint's `per` and `symfony` are not accepted as Pun presets. `pun migrate` expands them into explicit rules over `empty`.

## Lint sets

Sets select groups of lint rules. A rule can belong to several sets. Selected rules default to `"error"`:

| Set | What it turns on |
| --- | --- |
| `dead-code` | Code that never runs, or whose result is never used |
| `modernize` | Newer PHP syntax, up to your `[php] version` |
| `code-quality` | Simpler, clearer equivalents and likely bugs |
| `types` | Missing type declarations and PHPDoc types |
| `early-return` | Early returns and continues instead of nesting |
| `privatization` | Narrower visibility, final classes and constants |
| `naming` | Names that match their types; currently no rules after upstream deprecations |
| `coding-style` | One consistent way to write the same thing |

```toml pun.toml
[lint]
sets = ["dead-code", "modernize"]
```

Ecosystem rules depend on packages detected in `composer.lock`. PHP upgrade rules depend on the target PHP version. Rules outside sets can be enabled by name or group.

See [lint configuration](/docs/configuration/pun-toml#lint) for precedence and path overrides.

## Analyse presets

Analyse presets map PHPStan levels into five groups. Each includes the lower presets:

| Preset | PHPStan levels | Adds |
| --- | --- | --- |
| `basic` | 0–1 | Unknown classes, functions and methods on `$this`, wrong argument counts, undefined variables |
| `essential` | 2–3 | Unknown methods and properties on every expression, PHPDoc, return and property types |
| `recommended` | 4–5 | Dead code, constant conditions, argument types; the default |
| `strict` | 6–8 | Missing typehints; union types and nullables checked |
| `max` | 9–10 | Explicit and implicit `mixed` checked |

```toml pun.toml
[analyse]
preset = "strict"
```

The mapping does not imply complete PHPStan-level support. Some rules remain Planned, and preset type switches are not yet applied by the analysis CLI. See [analysis limitations](/docs/commands/analyse#configuration).

## Coming from PHPStan levels

`pun migrate` selects the containing preset and writes explicit rule differences for your PHPStan level. Numeric `[analyse] level` is not accepted in `pun.toml`.
