---
title: pun.toml
description: The one config file for every Pun command, with Pun's own rule IDs.
---

Pun reads only `pun.toml`. Write it with [`pun migrate`](/docs/commands/migrate), or by hand. Every section is optional:

```toml pun.toml
[php]
version = "8.4"                       # override; the default comes from composer.json's "require.php"

[files]                               # shared by every command
paths = ["app", "tests"]              # what to check when no paths are given
exclude = ["build", "storage"]

[format]
preset = "laravel"                    # laravel | psr12 | empty
exclude = ["app/Generated"]           # added to [files] exclude, for format only
not-name = ["*.blade.php"]
not-path = ["app/Legacy.php"]

[format.rules]                        # only what differs from the preset
"imports/ordered" = { sort = "length", case-sensitive = true }
"operators/concat-spacing" = "one"    # a rule with one option takes its value directly
"arrays/syntax" = false

[lint]
sets = ["dead-code", "modernize"]

[lint.groups]                         # a level for a whole group
style = "warn"
laravel-12 = "error"                  # turn an upgrade on

[lint.rules]                          # a rule's own line wins over its group
"style/require-final-class" = "error"
"style/require-ordered-traits" = { level = "warn", fix = "off" }
"types/no-loose-comparison" = "off"

[[lint.overrides]]
files = ["tests/**"]
rules = { "style/require-final-class" = "off" }

[analyse]
preset = "recommended"                # basic | essential | recommended | strict | max
exclude = ["tests/**"]                # added to [files] exclude, for analyse only
baseline = "pun-baseline.toml"

[analyse.rules]
"types/missing-return-type" = "off"
"undefined/method" = { magic = true } # options in a table mean "on, with these options"
```

## [php] and [files]

| Key | Meaning |
| --- | --- |
| `[php] version` | The PHP version rules target, as `major.minor`. Without it, the lowest version composer.json's `require.php` allows (`^8.4` gives 8.4), else 8.4 |
| `[files] paths` | What every command checks when no paths are given |
| `[files] exclude` | What every command skips. Each command's own `exclude` adds to it |

`vendor/` is never checked, nor are dot folders such as `.git`.

An `exclude` entry with `*`, `?`, `[` or `{` is a glob matched against the path from the project root, as in Mago: `storage/**` skips `storage/` but not `app/storage/`, and `*` also matches `/`. Any other entry is a path from the project root that skips itself and everything under it (`build` skips `build/`). Format is the exception: a plain entry in `[files] exclude` or `[format] exclude` keeps Pint's meaning, a folder of that name at any depth, and format also skips what Pint's finder skips. Run [`pun list-files`](/docs/commands/list-files) to see the result.

## [format]

| Key | Meaning |
| --- | --- |
| `preset` | `laravel` (default), `psr12` or `empty` |
| `exclude` | Added to `[files] exclude`, for format only. Plain entries are folders, as in Pint's finder; globs match from the project root |
| `not-name`, `not-path` | File names and paths format skips, as in Pint's finder |
| `rules` | `true`, `false`, a table of options, or the value of a rule's only option |

Format rules only change layout, casing and spelling. Risky ones, like `final_class` or `strict_comparison` in PHP-CS-Fixer terms, and the ones that delete or restructure code, like `no_unused_imports`, are [lint rules](/docs/commands/lint). Pint's `per` and `symfony` presets are not format presets: `pun migrate` writes a `pint.json` that used one as `empty` plus its rules.

## [lint]

| Key | Meaning |
| --- | --- |
| `sets` | The [lint sets](/docs/configuration/presets#lint-sets) to turn on: `dead-code`, `modernize`, `code-quality`, `types`, `early-return`, `privatization`, `naming`, `coding-style` |
| `exclude` | Added to `[files] exclude`, for lint only |
| `groups` | `"error"`, `"warn"` or `"off"` for every rule of a group |
| `rules` | `"error"`, `"warn"` or `"off"` per rule, or a table with `level`, `fix = "off"` and the rule's options |
| `[[lint.overrides]]` | `files` (globs) and `rules`: rule levels for the files they match |

A rule a set turns on is an `error`. A group's level wins over the sets, and a rule's own line wins over its group. A table without `level` is `error`. Only `error` fails a run. `--fix` applies the fix of every enabled rule; `fix = "off"` keeps a rule report-only.

Not yet at run time: a `warn` rule still fails a run like an `error` one, and `[[lint.overrides]]` are checked but not yet applied per file.

The Laravel, Pest and PHPUnit rules of a set run when composer.lock locks `laravel/framework`, `pestphp/pest` or `phpunit/phpunit`. Switch one off with its group: `[lint.groups] laravel = "off"`. A set's PHP upgrade rules (`php-8.4/...`) run from that `[php] version` on; upgrade groups such as `laravel-12` run when you turn the group on.

## [analyse]

| Key | Meaning |
| --- | --- |
| `preset` | `basic`, `essential`, `recommended` (default), `strict` or `max`; each includes the ones before it |
| `paths` | What analyse checks, instead of `[files] paths` |
| `exclude` | Added to `[files] exclude`, for analyse only |
| `baseline` | The baseline file |
| `rules` | `"on"`, `"off"` or a table of options per rule; `"on"` or `"off"` per group |

Analyse rules are on or off; every finding is an error. The Laravel rules run when composer.lock locks `laravel/framework`; `[analyse.rules] laravel = "off"` switches them off.

## Rule names

Rules use Pun IDs of the form `<command>/<group>/<name>`: `format/imports/ordered`, `lint/style/require-final-class`, `analyse/undefined/method`. Inside a `[<command>.rules]` table the command is implied, so the key is `"imports/ordered"` (quoted, because of the `/`). Groups are one fixed list shared by all three commands: topics such as `arrays`, `imports`, `phpdoc` and `types`, the ecosystems `laravel`, `pest`, `phpunit` and `doctrine`, and one upgrade group per target such as `php-8.4`. There are no aliases: an earlier Pun name (`ordered-imports`), a PHP-CS-Fixer name (`ordered_imports`), a PHPStan identifier (`method.notFound`) or a rule of another command gets an error that names its Pun ID, so a copied rule is never silently ignored. `pun config` prints everything resolved.

## Format rule options

Options have Pun names in kebab-case, and so do their values. Most are PHP-CS-Fixer's with `_` written as `-`
(`on_multiline = "ensure_fully_multiline"` is `on-multiline = "ensure-fully-multiline"`); PHP keywords such as
`require_once` keep their spelling. A few read better under new names:

| Rules | PHP-CS-Fixer | Pun |
| --- | --- | --- |
| `imports/ordered`, `attributes/ordered`, `types/ordered`, `phpdoc/types-order` | `sort_algorithm = "alpha"` | `sort = "alphabetical"` |
| `classes/ordered-interfaces` | `order = "alpha"`, `direction = "ascend"` / `"descend"` | `sort = "alphabetical"`, `direction = "ascending"` / `"descending"` |
| `imports/ordered` | `imports_order` | `order` |
| `types/ordered`, `phpdoc/types-order` | `null_adjustment = "always_first"` / `"always_last"` | `null-position = "first"` / `"last"` |
| `comments/header` | `comment_type = "PHPDoc"` | `comment-type = "phpdoc"` |

TOML has no `null`. Where PHP-CS-Fixer uses `null` for "leave it alone", Pun writes `"ignore"`
(`"control-flow/yoda" = { less-and-greater = "ignore" }`, `"operators/binary-spacing" = { operators = { "|" = "ignore" } }`).
`types/union-spacing` writes `space-multiple-catch = "same-as-space"`. For `imports/ordered`'s `order` and
`comments/header`'s `validator`, `null` is the option left out.

A rule with a single option that isn't `true`/`false` or a table takes its value directly: `"arrays/syntax" = "long"`
is `"arrays/syntax" = { syntax = "long" }`.

An unknown option or value is an error that lists what the rule takes, and a PHP-CS-Fixer name gets the Pun one:

```text
pun.toml: `imports/ordered` has no option `sort-algorithm`: use `sort`
pun.toml: `arrays/syntax` option `syntax` = "medium": expected one of "long", "short"
```

`pun migrate` translates PHP-CS-Fixer's names and values, and `pun config` prints options under Pun's. Every rule's
options are listed in `crates/pun-config/rules/mapping.toml`, under `[options."format/<group>/<name>"]`.

## Removed keys

Each of these is an error that names what to write instead:

| Written | Write instead |
| --- | --- |
| top-level `preset = "recommended"` | `[lint] sets` and `[analyse] preset` |
| `[format] paths` | `[files] paths` |
| `[format] preset = "per"` or `"symfony"`, or `--preset per` / `symfony` (exit 2) | `preset = "empty"` with the rules under `[format.rules]` (`pun migrate` writes them) |
| `fix = "apply"` | nothing: `--fix` applies every enabled rule |
| `fix = "safe-only"` | nothing, or `fix = "off"` to keep the rule report-only |
| `"info"`, or `severity` in a rule table | `"warn"`, and `level` |
| `true` / `false` for a lint rule | `"error"` / `"off"` |
| `[analyse] level = 5` | `[analyse] preset = "recommended"` |

## Without pun.toml

Every command stops with:

```text
No pun.toml found. Run `pun migrate`, or `pun init` for a new project.
```

`--preset <name>` (`laravel`, `psr12` or `empty`) or `--no-config` runs a built-in preset without a file, as in Pint.
