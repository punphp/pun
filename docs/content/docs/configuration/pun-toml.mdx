---
title: pun.toml
description: The one config file for every Pun command, with Pun's own rule IDs.
---

Pun reads only `pun.toml`. Write it with [`pun migrate`](/docs/commands/migrate), or by hand:

```toml pun.toml
preset = "recommended"        # lint + analyse tier: essential, recommended, strict, pedantic
laravel = true                # add-ons: laravel, pest, phpunit

[php]
version = "8.4"

[format]
preset = "laravel"            # Pint's preset; its risky and code-deleting rules are lint rules
exclude = ["build"]

[format.rules]
"operators/concat-spacing" = { spacing = "one" }
"arrays/syntax" = false

[lint.rules]
"style/require-final-class" = { fix = "apply" }   # applied by pun lint --fix / pun check --fix
"types/no-loose-comparison" = "warn"              # reported, never applied

[analyse]
paths = ["app", "tests"]
baseline = "pun-baseline.toml"
rules."types/missing-iterable-value-type" = "off"
```

## Top level

| Key | Meaning |
| --- | --- |
| `preset` | The [tier](/docs/configuration/presets) for lint and analyse |
| `laravel`, `pest`, `phpunit` | Add-ons: each turns on that ecosystem's rules within the tier |
| `[php] version` | The PHP version rules target |

## [format]

| Key | Meaning |
| --- | --- |
| `preset` | `laravel` (default), `per`, `psr12`, `symfony` or `empty` |
| `paths` | Paths to format when none are given |
| `exclude`, `not-name`, `not-path` | Folders, file names and paths to skip |
| `rules` | `true`, `false`, or an options table, per rule |

Format rules only change layout, casing and spelling. Risky ones, like `final_class` or `strict_comparison` in PHP-CS-Fixer terms, and the ones that delete or restructure code, like `no_unused_imports`, are [lint rules](/docs/commands/lint).

## [lint] and [analyse]

`[lint.rules]` takes a severity (`"error"`, `"warn"`, `"info"`, `"off"`) or a table with `fix` (`"apply"`, `"safe-only"`, `"off"`) and the rule's options. `[analyse]` takes its own `preset`, `paths`, `baseline` and `rules`.

## Rule names

Rules use Pun IDs of the form `<command>/<group>/<name>`: `format/imports/ordered`, `lint/style/require-final-class`, `analyse/undefined/method`. Inside a `[<command>.rules]` table the command is implied, so the key is `"imports/ordered"` (quoted, because of the `/`). Groups are one fixed list shared by all three commands: topics such as `arrays`, `imports`, `phpdoc` and `types`, the ecosystems `laravel`, `pest`, `phpunit` and `doctrine`, and one upgrade group per target such as `php-8.4`. There are no aliases: an earlier Pun name (`ordered-imports`), a PHP-CS-Fixer name (`ordered_imports`) or a rule of another command gets an error that names its Pun ID, so a copied rule is never silently ignored. `pun config` prints everything resolved.

## Without pun.toml

Every command stops with:

```text
No pun.toml found. Run `pun migrate`.
```

`--preset <name>` or `--no-config` runs a built-in preset without a file, as in Pint.
