---
title: pun.toml
description: One config file for format, lint and analyse. Pun also reads pint.json, phpstan.neon and rector.php as they are.
---

A project needs one file. Write it by hand, or let [`pun migrate`](/docs/commands/migrate) write it from your current configs.

```toml pun.toml
preset = "recommended"        # lint + analyse tier: essential, recommended, strict, pedantic
laravel = true                # add-ons: laravel, pest, phpunit

[php]
version = "8.4"

[format]                      # Pint presets; tiers don't apply to format
preset = "laravel"
rules.ordered-imports = { sort-algorithm = "alpha" }

[lint]
rules.prefer-early-return = "error"
rules.no-loose-comparison = "off"

[analyse]
preset = "strict"             # per-command override of the tier
paths = ["app", "tests"]
baseline = "pun-baseline.toml"
rules.missing-iterable-value-type = "off"
```

## Top level

| Key | Meaning |
| --- | --- |
| `preset` | The [tier](/docs/configuration/presets) for lint and analyse: `essential`, `recommended`, `strict`, `pedantic` |
| `laravel`, `pest`, `phpunit` | Add-ons. Each turns on that ecosystem's rules within the tier |
| `[php] version` | The PHP version rules target, such as `"8.4"` |

## [format]

Everything `pint.json` holds: `preset` (`laravel`, `per`, `psr12`, `symfony`, `empty`), `paths`, `exclude`, `not-name`, `not-path`, and `rules`. Keys set here win over `pint.json`'s, key by key.

## [lint] and [analyse]

Each takes its own `preset` to override the top-level tier, `paths`, and `rules.<name>` set to `"error"`, `"warning"`, `"off"` or an options table. `[analyse]` also takes `baseline`.

## Without pun.toml

Pun reads `pint.json`, `phpstan.neon` and `rector.php` directly, so trying it needs no changes, and prints a one-line hint to run `pun migrate`. Run `pun config --show` to see the resolved configuration either way.

:::tip
Unknown keys are an error, so typos are caught before they silently do nothing.
:::
