---
title: pun.toml
description: Paths, exclusions, presets, rule levels, and options.
---

Pun reads `pun.toml`. [`pun init`](/docs/commands/init) creates it; [`pun migrate`](/docs/commands/migrate) converts existing tool configs. Every section is optional.

This example shows the main settings:

```toml pun.toml
[php]
version = "8.4"

[files]
paths = ["app", "tests"]
exclude = ["build", "storage"]

[format]
preset = "laravel"
exclude = ["app/Generated"]
not-name = ["*.blade.php"]
not-path = ["app/Legacy.php"]

[format.rules]
"imports/ordered" = { sort = "length", case-sensitive = true }
"operators/concat-spacing" = "one"
"arrays/syntax" = false

[lint]
sets = ["dead-code", "modernize"]

[lint.groups]
style = "warn"

[lint.rules]
"style/require-final-class" = "error"
"style/require-ordered-traits" = { level = "warn", fix = "off" }
"types/no-loose-comparison" = "off"

[[lint.overrides]]
files = ["tests/**"]
rules = { "style/require-final-class" = "off" }

[analyse]
preset = "recommended"
exclude = ["tests/**"]

[analyse.rules]
"types/missing-return-type" = "off"
```

## [php] and [files]

| Key | Meaning |
| --- | --- |
| `[php] version` | Target PHP version as `major.minor`. Default: lowest version allowed by `composer.json` `require.php`, otherwise 8.4 |
| `[files] paths` | Default paths when no command-line paths are given |
| `[files] exclude` | Shared exclusions, combined with command-specific exclusions |

`vendor/` is never checked, nor are dot folders such as `.git`.

Entries containing `*`, `?`, `[` or `{` are globs relative to the project root. `*` also matches `/`. For example, `storage/**` skips root-level `storage`, not `app/storage`.

Other entries exclude a project-relative path and its descendants. Format retains Pint's exception: plain entries match folders at any depth. [`pun list-files`](/docs/commands/list-files) shows the selected files.

## [format]

| Key | Meaning |
| --- | --- |
| `preset` | `laravel` (default), `psr12` or `empty` |
| `exclude` | Added to `[files] exclude`, for format only. Plain entries are folders, as in Pint's finder; globs match from the project root |
| `not-name`, `not-path` | File names and paths format skips, as in Pint's finder |
| `rules` | `true`, `false`, a table of options, or the value of a rule's only option |

Format rules change layout, casing, and spelling. Risky and code-deleting fixers are [lint rules](/docs/commands/lint). Migration expands Pint's `per` and `symfony` presets into explicit rules over `empty`.

`not-name` and `not-path` accept Pint-style patterns, including PHP regular expressions. An invalid regex is a run error.

## [lint]

| Key | Meaning |
| --- | --- |
| `sets` | The [lint sets](/docs/configuration/presets#lint-sets) to turn on: `dead-code`, `modernize`, `code-quality`, `types`, `early-return`, `privatization`, `naming`, `coding-style` |
| `exclude` | Added to `[files] exclude`, for lint only |
| `groups` | `"error"`, `"warn"` or `"off"` for every rule of a group |
| `rules` | `"error"`, `"warn"` or `"off"` per rule, or a table with `level`, `fix = "off"` and the rule's options |
| `[[lint.overrides]]` | `files` (globs) and `rules`: rule levels for the files they match |

Selection applies in this order, with later settings taking precedence:

1. Sets, at `"error"`.
2. Groups.
3. Individual rules.
4. Matching path overrides, in declaration order.
5. Command-line `-A`, `-W`, and `-D`, in argument order.

A table without `level` defaults to `"error"`. Warnings do not fail unless a warning limit is set. `--fix` applies available fixes except rules with `fix = "off"`.

Laravel, Pest, and PHPUnit set rules depend on packages detected in `composer.lock`. PHP upgrade rules depend on `[php] version`. Groups such as `laravel-12` require explicit selection.

## [analyse]

| Key | Meaning |
| --- | --- |
| `preset` | `basic`, `essential`, `recommended` (default), `strict` or `max`; each includes the ones before it |
| `paths` | What analyse checks, instead of `[files] paths` |
| `exclude` | Added to `[files] exclude`, for analyse only |
| `baseline` | The baseline file |
| `stubs` | Stub files, as PHPStan's `stubFiles`: their PHPDoc refines vendor symbols |
| `rules` | `"on"`, `"off"` or a table of options per rule; `"on"` or `"off"` per group |
| `[[analyse.ignore]]` | Errors to ignore, as PHPStan's `ignoreErrors` |

Analyse rules are on or off. Every finding is an error.

An ignore entry names a `rule`, an `identifier`, a `message` (a PCRE pattern) or a `raw-message` (the exact text), and optionally `paths` (paths or fnmatch patterns, relative to the project) and a `count` (with one path). An error is ignored when it matches every key given. An entry nothing matched, or a `count` that doesn't hold, is an error with PHPStan's message. Migration writes these tables from `ignoreErrors`:

```toml
[[analyse.ignore]]
rule = "undefined/method"
message = "#^Call to an undefined method App\\\\Models\\\\User::#"
paths = ["app/Http/*"]
```

## Rule names

Rule IDs use `<command>/<group>/<name>`, such as `format/imports/ordered`. Omit the command inside its rules table: `[format.rules]` uses `"imports/ordered"`.

Groups describe topics, ecosystems, or upgrade targets. The [rule directory](/docs/rules) lists them.

Config accepts no upstream or old-name aliases. Invalid names produce an error with the current Pun ID. `pun explain <name>` accepts upstream names for lookup; `pun config` prints resolved settings.

## Rule options

Option names and most string values use kebab-case. For example, PHP-CS-Fixer's `on_multiline = "ensure_fully_multiline"` becomes `on-multiline = "ensure-fully-multiline"`. PHP keywords such as `require_once` retain their spelling.

Some options have different names:

| Rules | PHP-CS-Fixer | Pun |
| --- | --- | --- |
| `imports/ordered`, `attributes/ordered`, `types/ordered`, `phpdoc/types-order` | `sort_algorithm = "alpha"` | `sort = "alphabetical"` |
| `classes/ordered-interfaces` | `order = "alpha"`, `direction = "ascend"` / `"descend"` | `sort = "alphabetical"`, `direction = "ascending"` / `"descending"` |
| `imports/ordered` | `imports_order` | `order` |
| `types/ordered`, `phpdoc/types-order` | `null_adjustment = "always_first"` / `"always_last"` | `null-position = "first"` / `"last"` |
| `comments/header` | `comment_type = "PHPDoc"` | `comment-type = "phpdoc"` |

TOML has no `null`. Where PHP-CS-Fixer uses `null` for "leave it alone", Pun writes `"ignore"`
(`"control-flow/yoda" = { less-and-greater = "ignore" }`, `"operators/binary-spacing" = { operators = { "|" = "ignore" } }`).
`types/union-spacing` writes `space-multiple-catch = "same-as-space"`. For `imports/ordered`'s `order` and
`comments/header`'s `validator`, `null` is the option left out.

A rule with a single option that isn't `true`/`false` or a table takes its value directly: `"arrays/syntax" = "long"`
is `"arrays/syntax" = { syntax = "long" }`.

An unknown option or value is an error that lists what the rule takes, and a PHP-CS-Fixer name gets the Pun one:

```text
pun.toml: `imports/ordered` has no option `sort-algorithm`: use `sort`
pun.toml: `arrays/syntax` option `syntax` = "medium": expected one of "long", "short"
```

The lint rules a PHP-CS-Fixer fixer runs (the risky and code-deleting ones) name their options the same way, beside
`level` and `fix`: `"phpunit/require-method-casing" = { case = "snake-case" }`,
`"phpdoc/no-superfluous-tags" = { allow-mixed = true }`.

Lint rules ported from Mago's linter take Mago's option names and defaults, beside `level` and `fix`:
`"complexity/no-excessive-cyclomatic" = { threshold = 20, method-threshold = 10 }`,
`"security/no-restricted-functions" = { functions = ["exec", { name = "eval", help = "Use a parser." }], extensions = ["curl"] }`.
Mago's per-rule `level` and the `level` of a `functions`, `extensions` or `types` entry are accepted and not used:
the rule's level comes from pun.toml. `style/require-naming-convention` stands for Mago's nine `*-name` rules and
takes one table per Mago code, each with `enabled` and that rule's options:
`"style/require-naming-convention" = { method-name = { enabled = true, camel = false }, class-name = { psr = true } }`.
As in Mago, its method, property and variable checks are off until enabled.

`pun migrate` translates names and values. The [rule reference](/docs/rules) lists options for each rule.

## Removed keys

Each of these is an error that names what to write instead:

| Written | Write instead |
| --- | --- |
| top-level `preset = "recommended"` | `[lint] sets` and `[analyse] preset` |
| `[format] paths` | `[files] paths` |
| `[format] preset = "per"` or `"symfony"`, or `--preset per` / `symfony` (exit 2) | `preset = "empty"` with the rules under `[format.rules]` (`pun migrate` writes them) |
| `fix = "apply"` | nothing: `--fix` applies every enabled rule |
| `fix = "safe-only"` | nothing, or `fix = "off"` to keep the rule report-only |
| `"info"`, or `severity` in a rule table | `"warn"`, and `level` |
| `true` / `false` for a lint rule | `"error"` / `"off"` |
| `[analyse] level = 5` | `[analyse] preset = "recommended"` |

## Without pun.toml

Commands that load config stop with:

```text
No pun.toml found. Run `pun migrate`, or `pun init` for a new project.
```

`--preset <name>` (`laravel`, `psr12` or `empty`) or `--no-config` runs a built-in preset without a file, as in Pint.
