---
title: Delegate mode
description: How Pun stays Pint-identical for rules it hasn't ported natively.
---

If an enabled rule has no native port, Pun runs the files through the real PHP-CS-Fixer. Output stays identical to Pint, while discovery, caching, reporting and exit codes stay Pun's.

## How it runs

- **Whole files.** PHP-CS-Fixer runs every fixer once, by priority, on one token list, and unported rules sit between native ones. So one unported rule sends every file of that run through PHP, rather than mixing the two mid-file.
- **Long-lived workers.** A pool of `php` workers, one per thread that needs one, receives each file and returns the result. Fixers resolve through PHP-CS-Fixer's own config resolver, so validation messages are upstream's.
- **Runtime.** System `php` plus the first of: `$PUN_PINT` (a Pint PHAR), the project's `vendor/laravel/pint`, or its `vendor/autoload.php` when it has `friendsofphp/php-cs-fixer`.

## Seeing and skipping it

```bash
pun format --explain       # why, and which fixers ran in PHP
pun format -v              # just the reason
pun format --native-only   # skip delegated rules and list them
```

:::warning
`--native-only` output is not Pint-identical. It's for trying Pun on a machine without PHP, not for CI.
:::

## Cache

The cache signature includes the PHP runtime and `vendor/composer/installed.json`, so upgrading Pint or PHP-CS-Fixer invalidates it. Pass `--no-cache` to check every file.
