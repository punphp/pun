## Config translation

Pun reads only pun.toml. `pun migrate` leaves the source config in place. Unported rules and unsupported items are named and skipped, with a request to send a PR. There is no PHP fallback.

Run `pun migrate --from phpstan`. PHPStan config includes are resolved before migration.

| phpstan.neon | pun.toml |
| --- | --- |
| `level: 5` | `[analyse] preset = "recommended"`, plus explicit on/off lines for exactly level 5 |
| `level: 0..10` | The containing analyse preset, with on/off differences; no numeric Pun levels |
| `paths`, `excludePaths`, `stubFiles` | `[analyse] paths`, `exclude`, `stubs` |
| `ignoreErrors` identifiers, patterns, paths, count | `[[analyse.ignore]]` with Pun `rule`, original `identifier`, `message`, `paths`, `count` |
| Changed rule parameters | Kebab-case options on each running rule that reads the parameter |
| strict-rules or deprecation-rules includes | Their built-in Pun checks, only when their parameter enables them |
| `@phpstan-ignore method.notFound` | `@pun-ignore analyse/undefined/method` |
| Baselines | Not copied. Run `pun analyse --generate-baseline`. |
| Custom extensions, bleeding edge | Named and skipped. Send a PR. |

The table is at identifier level, not PHPStan class level. Pattern entries are expanded against the pinned inventories; exact identifiers take precedence over patterns, just as they do during migration.
