## Config translation

`pun migrate` leaves source configs in place and reports skipped items. Planned rules are not implemented. Pun never falls back to PHP for missing rules.

Run `pun migrate --from rector` after `composer install`. The project's own Rector resolves `rector.php` with system PHP.

| rector.php | pun.toml |
| --- | --- |
| `->withPreparedSets(deadCode: true)` | `[lint] sets = ["dead-code"]` |
| `typeDeclarations: true` | The `types` lint set |
| PHP upgrade sets from PHP 8.4 | The `modernize` set, gated by the target version |
| Explicit rules and set differences | `[lint.rules]` at `"error"` or `"off"`, preserving the selected rules |
| `->withConfiguredRule()` | Rule options with kebab-case keys; lists under `items` |
| `->withPaths()`, path skips | `[lint] exclude` and `[[lint.overrides]]` |
| Closures, null values, custom rules, excluded sets | Reported and skipped |

Layout-only Rector rules map to format and are left to `[format]`. The migration reports when the format config does not run them.
